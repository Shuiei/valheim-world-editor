Translatable, faster and safer: the editor can be translated (Settings › Language), your unsaved changes survive the game saving the world under you, worlds saved by Valheim 1.0.20 can be saved again, a first (experimental) Mac build, big areas and live sessions stay smooth, and about a hundred fixes from a full review.

This release covers 1.44.0 to 1.47.29 (the versions in between were not published on their own; 1.46.0 was not used). The WorldEditorBridge plugin changed in 1.45.3 and 1.47.27: update it on the server so a lost answer can never make objects twice; an older plugin keeps working as before.

## Added

- **The editor can be translated.** Its texts are in language catalogues (`Core/Lang/en.json`); a catalogue dropped in the data folder's `lang` folder (`fr.json`, `pt-BR.json`…) translates the editor, English showing where it has no text yet. **Settings › Language** chooses the language, by default the computer's when there is a catalogue of it. Every page, tool, panel, dialog and message now comes from the catalogue; the names of objects, items and biomes in the save stay as they are, and Claude is still answered in English. How to translate: [docs/translating.md](https://github.com/Shuiei/valheim-world-editor/blob/main/docs/translating.md).
- **Your changes are kept when the game saved the world since you opened it.** Save was refused then, and the only way out was to leave the world and lose every unsaved change. The editor now offers to bring them over onto the game's save (ground, zone resets, No limit ground, deleted, added and moved objects with their data), asking once per kind whose version stays where the game changed the same zone or object. Nothing is written until you save.
- **A Mac build (experimental), for Apple silicon**: ValheimWorldEditor.app finds Valheim in Steam's libraries, the worlds, the game's log and r2modman's profiles where macOS keeps them; **Cmd** works as **Ctrl**. Intel Macs are not supported yet.

## Changed

- **Big areas and long live sessions stay smooth.** Dragging an Area selection, moving the mouse in the Select tool, moving or dropping a big selection, picking a saved selection, Regrow over many zones, long paths, spawn-point and nest markers, dungeon rooms and location parts, the map with many search results or zoomed in, and switching between the map and the 3D view no longer stall. Opening an area works out its ground in about half the time, a long live session no longer keeps every past read of the game in memory, and saving and Apply live no longer copy every edited zone or wait for the history file to be written. Deep dungeons and new worlds' locations are worked out faster.
- **Claude's scripts need your leave**: **Settings › Claude › Claude may run scripts** (off by default). A script runs in its own process, so a crash in it no longer takes the editor down, and **Stop** ends a script busy in one long call or an endless loop.
- **Every error the editor or the plugin catches is written to the log**, without your folders in it, so the log says what went wrong.

## Fixed

- **Worlds saved by Valheim 1.0.20 (save format 42) can be saved.** Each file keeps the format it was read in; new worlds are made in format 42, which Valheim 1.0.17 and earlier cannot open.
- **Saving**: a power cut just after saving could leave a broken save the game trusts; a failed save or Apply live still turned No limit ground into discs and cleared the undo history; one damaged ground record stopped the whole world from opening; a settings or selections file could be lost or written over with the defaults.
- **Live editing**: applying again after a lost answer could make every new object twice (needs the plugin from this release); objects just applied could vanish from the editor; an Apply live that failed partway said nothing was applied; a brush stroke made while Apply live answered could lose ground; a live map could show another world's players; Connect clicked twice opened two connections; a plugin that did not answer could freeze the window for up to 15 seconds.
- **Security**: other users of the computer could read Claude's token in the settings file; editing a saved server could send another server's password and token to it; in another language, Claude could use the Blueprints buttons that write or delete files; Claude could change a live world with Auto on through the editor's controls.
- **Tools**: moving objects past the area's edge sank them about 1000 m; mirrored pastes tilted pieces the wrong way; "Move there" moved the selection on every axis; Restore from backup with the Mask on doubled objects; Reset zones could miss zones depending on the Soft slider; trees grown on a mountain could float or be buried; replacing a ship's root left its parts behind; a piece dragged far did not snap where it was dropped; typing in a text box moved the camera.
- **Generated dungeons**: no more two kitchens or forges, antechambers leading nowhere, guards locked in the cells, furnishings off to one side in alcoved rooms, a sunken warning sign by the boss gate or steps rising away from a plinth.
- **Claude**: object ids could hit the wrong objects after another area was opened; dungeons Claude generated could land in the wrong place or go live; `set_control` clicks on switches changed nothing; Claude Desktop lost the MCP server on a batch request; `build_floor`, `build_walls` and `build_roof` could freeze the editor.
- **Robustness**: a model that failed to load, an unusual mod bundle, a hand-made language file, a damaged object or dungeon, a stamp picture that could not be read or a cache that could not be written no longer stop the editor, a world search or every model from drawing.

## WorldEditorBridge

- `/objects` takes an `X-Call-Id` header: a call already done under that id (one of the last 16) is answered again with what was done, not done twice. `/status` lists `"once"` among its features and gives `"run"`, a new id each time the game starts.
- Every error the plugin catches is logged in BepInEx's log, with the server's home folder written `~`.

See the [CHANGELOG](https://github.com/Shuiei/valheim-world-editor/blob/main/CHANGELOG.md) for the details.
