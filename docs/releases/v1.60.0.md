Expand World worlds, items on stands, a longer history and builds that stay put: worlds made with the Expand World mods are generated, mapped and edited as the mods make them, the 3D view draws what item and armour stands hold, the history keeps every change, moved objects and creatures land on the floor under them instead of in it, No limit ground loads before the buildings on it, and live objects follow what the game really does with them.

This release covers 1.47.30 to 1.60.0 (the versions in between were not published on their own). The WorldEditorBridge plugin changed in 1.54.0, 1.57.1, 1.57.2 and 1.57.3: update it on the server so a live world follows the Expand World mods the game runs, No limit ground loads first and the editor follows creatures and other moving objects; an older plugin keeps working as before.

## Added

- **Expand World support.** With the **Expand World** switch in Settings on, worlds made with Expand World Size, Expand World Rivers and Expand World Data are generated as those mods make them: the world's size and settings, rivers and water level, the data mod's biomes, world rules, territories, locations and vegetation. The map, the New world page and the 3D view follow them (a wider overview, the mods' biome names and map colours, their sea level), and a live world reads the mods' files from the game's own BepInEx folder through WorldEditorBridge. Worlds saved on Expand World Size's wider zone grid (up to about 65 km) open and save as they lie, switch on or off. The editor ships no copy of the YamlDotNet library the mods use: it reads the one in your BepInEx plugins folder. See [Expand World](https://github.com/Shuiei/valheim-world-editor/blob/main/addons/ExpandWorld/README.md).
- **The 3D view draws what item stands and armour stands hold**: a shield on the wall, a trophy, food on a table, an armour stand's armour, helmet, cape and weapons. They follow the stand and change at once when the inspector or Claude changes what it holds.
- **The history keeps every change by default.** **Settings › History › Steps kept** sets a number (empty or 0 keeps them all, within 2 GB of memory); the History panel shows the newest 200 and **Show older** adds more.
- **Creatures are never sunk into building pieces.** One put down, moved, pasted, placed by a script or brought by a blueprint with its feet inside a floor or wall stands on top of the piece instead, and the Workshop's support check counts those still inside one.
- **Blueprints say which pieces only the editor can place** (statues, ships, creatures, the T.W.I.G., which Homestead's hammer skips), and their cost leaves them out, so it is what a hammer user pays.
- **A double click on an object in the View tool switches to Select with it selected**, ready to move or turn.

## Changed

- **Moved objects land on what is under them, not only on the ground.** With **Put each object on the ground when moving** on, a chair, a chest or a creature you move ends up on the floor, stair or table under it where you let go; a building still moves as one block, its bottom layer put on the floor or platform under it.
- **No limit ground loads before the buildings on it.** Ground discs are saved so the game spawns them first: the ground is finished in the first frames instead of climbing for ten seconds or more on a big build while the game stutters. The plugin from this release changes the discs saved by older versions.
- **Live, the editor shows every object where the game really has it.** Objects you applied take the place and data the game gives them (a creature's health, where physics settled it), and creatures, ships, carts, items and fires are followed as they move or change (needs the plugin from this release).

## Fixed

- **A new world is saved where the installed game looks for it**: on Linux with Valheim run through Proton, a world made on the New world page could land in the native game's folder and never show in the game.
- **Apply live no longer fails now and then with "An error occurred while sending the request"** after about ten seconds without talking to the game.
- **Windows**: a save no longer fails when another program holds the file for a moment ("Access to the path is denied"); the editor no longer holds on to the YamlDotNet library in the BepInEx plugins folder or to files in the bundles folders, so a mod manager can update them.
- **A bed, a rug or another cut-out piece on a floor can be clicked again** instead of the floor under it.
- **The Dungeon panel no longer fails at the editor's start** ("“CryptKey” is not an item of the game").
- **The Workshop's support check no longer counts the parts of a piece that move on their own** (a door's leaf, a gate, a ship's hull).
- **Opening the Workshop during a live session no longer fills the log** with "Cannot access a disposed object".
- **A live world's Expand World settings are read again** from the world file the game now saves.

## WorldEditorBridge

- `GET /plugins`, `GET /config?path=` (files under `BepInEx/config`, 4 MB at most) and `GET /world/meta` (the world file the game saves, `_main.n.fwl2`, else the older `.fwl`) let the editor read the mods a live game runs; `/status` lists the feature `"files"`.
- Ground discs are kept first in line: the plugin puts discs the game turned back to the Solid kind back to Terrain every few seconds, and changes older editor versions' discs at the first look.
- `POST /watch` gives a second number per zone for the kinds that move or tick on their own, and `POST /zone/movers` serves only those kinds of the zones asked for.
