# การแปลเอดิเตอร์

ข้อความของเอดิเตอร์ อยู่ในแคตตาล็อก หนึ่งไฟล์ต่อหนึ่งภาษา: ไฟล์ JSON ของข้อความ ตามคีย์ ภาษาอังกฤษ
[`editor/Core/Lang/en.json`](../../editor/Core/Lang/en.json) คือต้นฉบับ ที่ใช้แปลแคตตาล็อกอื่นทั้งหมด

เอดิเตอร์มีภาษาอังกฤษ ฝรั่งเศส (`fr`) เยอรมัน (`de`) สเปน (`es`) โปรตุเกสแบบบราซิล (`pt-BR` ซึ่งแสดงด้วย
บนคอมพิวเตอร์ ที่ตั้งเป็นภาษาโปรตุเกส ของโปรตุเกส) ไทย (`th`) และฟิลิปิโน (`fil` แสดงบนคอมพิวเตอร์ที่ตั้งเป็นภาษาตากาล็อกด้วย) พร้อมเอกสารที่แปล เป็นแต่ละภาษา (`docs/th/`… ภาพประกอบ ถ่ายในภาษานั้น) เอดิเตอร์แสดงภาษาที่เลือกไว้ใน
**การตั้งค่า → ภาษา** โดยค่าเริ่มต้น คือภาษาของคอมพิวเตอร์ เมื่อมีแคตตาล็อกของภาษานั้น ข้อความที่แคตตาล็อก
ยังไม่มี จะแสดงเป็นภาษาอังกฤษ ภาษาใหม่จะมีผล เมื่อเปิดเอดิเตอร์ใหม่

ยังไม่ใช่ทุกข้อความ ที่มาจากแคตตาล็อก ข้อความต่อไปนี้มาจากแคตตาล็อก:

- คำแนะนำเมื่อชี้เมาส์ทุกรายการ (คำแนะนำของ ตัวตรวจดูข้อมูล ที่สร้างจากข้อมูลของวัตถุ จะใช้ชื่อตามที่เซฟเก็บไว้)
- หน้าเริ่มต้น การตั้งค่า แผนที่โลก หน้า โลกใหม่ และกล่องโต้ตอบเล็กๆ (คำถาม ข้อความ รายละเอียดของพิมพ์เขียว)
  พร้อมคำที่ใช้ร่วมกัน
- แถบด้านบนของเอดิเตอร์ 3D พร้อมสิ่งที่การบันทึก การนำไปใช้ การทิ้ง การออก และการปิดโปรแกรม ถามและแจ้ง
  ข้อความจากเกมไลฟ์ และผู้เล่น
- ค่าที่แสดงบนแถบสถานะ แผง ประวัติ แผง มุมมอง การ์ดวิธีใช้ และสิ่งที่แถบสถานะ กับ ประวัติ แจ้ง
  เกี่ยวกับการเปลี่ยนแปลงของ Claude
- เครื่องมือ: แปรงพร้อมแสตมป์ วัด มาสก์ สคริปต์ เส้นทาง ภูมิประเทศ เลือก วาง จัดวาง ก่อสร้าง
  (แผงและแถบก่อสร้าง) ขอบเขต เครื่องมือ ดันเจี้ยน พร้อมตัวสร้าง แผง พิมพ์เขียว เวิร์กช็อป
  และ ตัวตรวจดูข้อมูล
- ชื่อไบโอม

ส่วนที่เหลือ จะย้ายตามมาทีละหน้าต่าง แคตตาล็อกที่ทำตอนนี้ ยังใช้ได้ต่อไป เมื่อมีข้อความเพิ่ม: ข้อความใหม่
จะแสดงเป็นภาษาอังกฤษ จนกว่าจะแปล

## การสร้างแคตตาล็อก

1. คัดลอก `en.json` ไปไว้ในโฟลเดอร์ `lang` ของโฟลเดอร์ข้อมูลของเอดิเตอร์
   (`~/.local/share/ValheimWorldEditor/lang` บน Linux, `%LOCALAPPDATA%\ValheimWorldEditor\lang` บน
   Windows ซึ่ง **การตั้งค่า → ภาษา** แสดงไว้) ตั้งชื่อตามรหัสของภาษา: `fr.json`,
   `de.json`, `pt-BR.json`
2. แปลค่า ห้ามแปลคีย์ `lang.name` คือชื่อของภาษา ในภาษานั้นเอง ("Français") ตามที่
   การตั้งค่า แสดงในรายการ
3. คง `{0}`, `{1}`… ไว้ทุกตัว: เอดิเตอร์จะใส่ค่าลงตรงนั้น (โฟลเดอร์ ตัวเลข) ลำดับของค่า
   ในประโยค เปลี่ยนได้ ข้อความที่ตำแหน่งค่า ไม่ตรงกับภาษาอังกฤษ หรือมี `{` หรือ `}` เกินมา
   จะไม่ถูกใช้
4. เลือกภาษาใน **การตั้งค่า** เปิดเอดิเตอร์ใหม่ แล้วตรวจดู คีย์ที่คุณไม่ใส่ หรือลบออก
   จากสำเนาของคุณ จะแสดงเป็นภาษาอังกฤษ

โฟลเดอร์เดียวกันนี้ ยังรับการแก้ไขด้วย: ไฟล์ในโฟลเดอร์นั้น ที่มีรหัสของแคตตาล็อก ที่เอดิเตอร์มีอยู่
จะถูกวางทับ ทีละข้อความ ตรงนั้น คีย์ที่คุณไม่ใส่ (หรือข้อความที่ไม่ถูกใช้)
จะใช้คำแปลที่มีอยู่เดิม ภาษาอังกฤษ จะแสดงเฉพาะที่ไม่มีข้อความ ในทั้งสองแห่ง

ถ้าต้องการให้เอดิเตอร์ มีแคตตาล็อกของคุณ ให้เปิด pull request ที่เพิ่มไฟล์ลงใน `editor/Core/Lang/` (ใช้คีย์
จาก `en.json` เท่านั้น `LangCatalogueTests` จะตรวจคีย์)

## การแปลเอกสาร

หน้าต่างวิธีใช้ แสดงเอกสาร ในภาษาของเอดิเตอร์ เมื่อมีคำแปลของหน้านั้น และแสดงเป็นภาษาอังกฤษ
ในกรณีอื่น คำแปลของเอกสาร คือโฟลเดอร์ใน `docs/` ที่ตั้งชื่อตามรหัสของภาษา เหมือนแคตตาล็อก:
`docs/fr/`, `docs/pt-BR/` ไฟล์ `README.md` ของโฟลเดอร์เอง คือสิ่งที่ทำให้เป็นคำแปล (หน้าแรก และสารบัญ
ของหน้าต่างวิธีใช้) โฟลเดอร์ภาษาอังกฤษ (`guides/`, `help/`, `concepts/`, `start/`) ไม่มีไฟล์นี้

- **หน้า** โฟลเดอร์จำลองหน้าภาษาอังกฤษ: `docs/fr/map.md` แปล `docs/map.md` และ
  `docs/fr/guides/make-a-road.md` แปล `docs/guides/make-a-road.md` แปลหน้าที่หน้าต่างวิธีใช้แสดง
  ([writing-docs.md](../dev/writing-docs.md) แสดงรายการหน้า ที่ไม่ได้แสดง) หน้าที่ยังไม่ได้แปล จะแสดงเป็นภาษาอังกฤษ
  การแปลจึงเริ่มจากไม่กี่หน้าได้
- **ลิงก์** เขียนลิงก์ ตามที่หน้าภาษาอังกฤษเขียน จากในโฟลเดอร์: `map.md#…` และ `guides/x.md` จาก
  `docs/fr/README.md` หรือ `../area.md` จาก `docs/fr/guides/` ลิงก์ที่ออกนอก `docs/` จะขึ้นไป `../` มากกว่า
  ลิงก์ภาษาอังกฤษหนึ่งระดับ (`../../README.md`, `../../editor/Core/Lang/en.json`) และลิงก์ไปยังไฟล์ใน `docs/` ที่
  ไม่ได้แปล ก็เช่นกัน (`../worldeditor.schema.json`) ลิงก์ไปยังหน้า ที่โฟลเดอร์ยังไม่มี ยังใช้ได้ในเอดิเตอร์
  (ซึ่งแสดงหน้าภาษาอังกฤษ) แต่ใช้บน GitHub ไม่ได้ จนกว่าหน้านั้นจะได้รับการแปล
- **รูปภาพ** รูปภาพที่มีข้อความ จะถ่ายใหม่ในภาษาของคุณ ใน `docs/fr/images/` ด้วยชื่อเดิม และเขียนเป็น
  `images/x.webp` รูปที่ไม่มีอะไรให้แปล ใช้รูปภาษาอังกฤษได้: `../images/x.jpg` จนกว่ารูปภาพ
  ของ `images/` จะถูกเพิ่มในโฟลเดอร์ของคุณ หน้าต่างวิธีใช้ จะแสดงรูปภาษาอังกฤษ ที่ชื่อเดียวกัน
- **หัวข้อ** แปลหัวข้อ id ของหัวข้อ จะเปลี่ยนตาม (GitHub สร้าง id จากคำ: `#search-the-world`
  กลายเป็น `#rechercher-dans-le-monde`) และลิงก์ในคำแปลเอง ใช้ id ที่แปลแล้ว ตามที่ GitHub ต้องการ คง
  หัวข้อของหน้าภาษาอังกฤษไว้: จำนวนเท่ากัน ระดับเดียวกัน ลำดับเดียวกัน แล้วเอดิเตอร์ จะพา id ภาษาอังกฤษ
  ไปยังหัวข้อที่แปลแล้วด้วย ปุ่มวิธีใช้ (`F1` และ `?` ของแผง) ซึ่งอ้างถึงหัวข้อภาษาอังกฤษ จึงไปถึง
  ตำแหน่งที่ถูกต้อง
- **เครื่องหมายต้นฉบับ** ใส่บรรทัดหนึ่ง เป็นบรรทัดแรกของหน้า เพื่อบอกว่าแปลจาก ข้อความภาษาอังกฤษใด:
  `<!-- source: 1a2b3c4d -->` คือ 8 ตัวอักษรแรก ของ SHA-256 ของหน้าภาษาอังกฤษ (ทั้ง GitHub และหน้าต่างวิธีใช้
  ไม่แสดงบรรทัดนี้) หาค่าได้ด้วย `sha256sum docs/map.md | cut -c1-8` (macOS: `shasum -a 256`) เครื่องหมาย
  คำนวณจากหน้า ที่ใช้การขึ้นบรรทัดแบบ Unix: บน checkout ของ Windows ที่เปลี่ยนเป็น `\r\n` ให้ใช้
  `git show HEAD:docs/map.md | sha256sum | cut -c1-8` ซึ่งให้หน้าตามที่ repository เก็บไว้

เมื่อหน้าภาษาอังกฤษเปลี่ยน เครื่องหมายจะเปลี่ยนตาม: หน้าต่างวิธีใช้ ยังแสดงคำแปล พร้อมหมายเหตุว่า
หน้านี้เปลี่ยนในภาษาอังกฤษแล้ว และปุ่มที่แสดงหน้าภาษาอังกฤษ ถ้าต้องการปรับคำแปลให้ทันสมัย ให้ดูสิ่งที่
เปลี่ยนในภาษาอังกฤษ ตั้งแต่นั้น (`git log -p docs/map.md`) แปลส่วนนั้น แล้วเขียนเครื่องหมายใหม่ การทดสอบตรวจทุก
ลิงก์และรูปภาพของคำแปล และตรวจว่าคำแปลที่ทันสมัย มีหัวข้อของหน้าภาษาอังกฤษ

## สำหรับนักพัฒนา

- ข้อความที่ผู้ใช้เห็น จะอยู่ใน `en.json` ใต้คีย์ที่ตั้งชื่อ ตามที่ที่แสดงข้อความ
  (`settings.port` หรือ `common.cancel` สำหรับคำที่ใช้ทุกที่) และเรียกด้วย
  `Lang.T("settings.port")` หรือ `Lang.T("settings.worldNotFound", path)` พร้อมค่าสำหรับตำแหน่ง
  `{0}`… (ใส่ด้วย invariant culture) คำแนะนำเมื่อชี้เมาส์ คือคีย์ `tip.` ที่ให้ด้วย
  `.Tip("settings.port")` (ดู `editor/Desktop/Tips.cs`)
- เขียนคีย์เต็มในโค้ด แม้ตอนส่งต่อ: `LangCatalogueTests` ตรวจว่า ทุกคีย์
  ที่เรียกใช้ อยู่ใน `en.json` และทุกคีย์ของ `en.json` ถูกเรียกใช้ที่ใดที่หนึ่ง
- ข้อความสำหรับ Claude (คำอธิบาย และคำตอบของเครื่องมือ MCP) ล็อก เอาต์พุตของบรรทัดคำสั่ง และ
  รูปแบบไฟล์ คงเป็นภาษาอังกฤษ และอยู่นอกแคตตาล็อก ข้อความที่แสดงต่อผู้ใช้ และ Claude
  ได้รับด้วย (ค่าใช้จ่ายของชิ้นส่วน) จะขอภาษาอังกฤษ ด้วย `Lang.En` ฝั่ง Claude
- หน้าต่างถูกสร้างครั้งเดียว ในภาษาที่ใช้ตอนเริ่ม (`Lang.Use` ใน `Program.Main`) ไม่มีอะไร
  ต้องคอยฟังการเปลี่ยนภาษา

### การตั้งชื่อคีย์

- ส่วนแรก คือหน้าต่าง สะกดแบบเดียวกับคีย์ tip ของหน้าต่างนั้น (`area`, `place`, `select`, `path`,
  `blueprints`, `newWorld`…) เครื่องมือที่เปลี่ยนชื่อในหน้าต่าง ยังใช้คีย์เดิม: คีย์ของเครื่องมือ ขอบเขต คือ `area.*` และ
  ชนิดของเครื่องมือ ภูมิประเทศ ยังใช้ `shape.*` (สูตร) และ `mountain.*` ข้าง `landform.*` คำนำหน้าที่ใช้ร่วมกัน: `common.*` สำหรับคำที่ใช้ในสามหน้าต่างขึ้นไป
  (OK, Yes, Cancel, Save, Discard, Stay, Keep them…) `dialog.*` สำหรับกล่องโต้ตอบเล็กๆ `save.*` สำหรับ
  คำถามเรื่องการบันทึก การนำไปใช้ การทิ้ง และการออก `biome.*` สำหรับชื่อไบโอม
- ส่วนกลาง บอกชนิดของข้อความ: `label` (ป้ายแถว ปุ่ม สวิตช์) `head`
  (หัวข้อส่วน) `hint` (คำอธิบายสีจาง) `msg` (แถบสถานะ และผลลัพธ์) `undo` (ป้ายใน ประวัติ)
  `error` (ปัญหาที่แสดงในแผง) `ask.<name>.title|text|yes|no` (คำถาม) หรือ
  ชื่อของรายการ สำหรับรายการย่อย (`brush.falloff.flatTop`) ข้อความเดี่ยวของหน้าต่าง ใช้สองส่วนก็ได้
  (`settings.port`) ส่วนสุดท้าย เป็น camelCase
- คำภาษาอังกฤษหนึ่งคำ มีคีย์เดียว: ใช้ `common.*` ซ้ำ แทนการเพิ่ม "Save" อีก ชื่อที่ Claude ใช้
  เรียกตัวควบคุมของหน้าต่าง คำนวณจากภาษาอังกฤษ (`Lang.EnglishOf`) ซึ่งต้องอาศัยกฎนี้
- ข้อความที่ย้ายเข้าแคตตาล็อก ใช้ถ้อยคำเดิม เปลี่ยนถ้อยคำ ในการเปลี่ยนแปลงแยกต่างหาก
- ข้อความของ enum มาจาก `switch` ที่ระบุคีย์เต็มทุกตัว ห้ามใช้ `"prefix." + value`

### ค่า พหูพจน์ และประโยค

- ค่าจะใส่ลงใน `{0}`, `{1}`… โดยมีรูปแบบและหน่วย อยู่ในข้อความ (`"{0:0.0} m"`,
  `"{0} × {1} zones"`) เป็นตัวเลขและชื่อดิบ ไม่ใช่สตริงที่จัดรูปแบบแล้ว คีย์หนึ่ง จะถูกเรียก
  ด้วยจำนวนค่าเท่าเดิมเสมอ ข้อความที่เรียกพร้อมค่า จะเขียนวงเล็บปีกกาจริงซ้ำสองตัว (<code>&#123;&#123;</code>)
  ข้อความที่เรียกโดยไม่มีค่า จะไม่มีวงเล็บปีกกาเลย
- ชื่อที่อยู่ในภาษาของผู้ใช้แล้ว (ไบโอม ชนิดของวัตถุ) จะใส่เข้าไปเป็นค่า อย่าเปลี่ยนตัวพิมพ์
  ให้เข้ากับประโยค (`ToLowerInvariant`): เขียนประโยคล้อมชื่อนั้นแทน
- ไม่มีกฎพหูพจน์ คง "object(s)" ไว้ในข้อความเดียว ตรงที่โค้ดเลือกระหว่าง
  หนึ่งกับหลายอยู่แล้ว ให้ใช้คีย์เต็มสองคีย์ (`….one`, `….many`) ห้ามเติมคำลงท้ายในโค้ด
- หนึ่งคีย์ต่อหนึ่งประโยคเต็ม ประโยคเสริมที่ไม่บังคับ เป็นคีย์ของตัวเอง ต่อด้วยช่องว่าง
  ห้ามต่อส่วนต่างๆ ของประโยคเข้าด้วยกัน รายการของชื่อที่แปลแล้ว ต่อกันด้วย ", "

### สิ่งที่คงเป็นภาษาอังกฤษ

- ทุกอย่างที่ Claude อ่าน: คำอธิบาย และคำตอบของเครื่องมือ MCP (`ClaudeTools*`, `ClaudeGuide`)
  ล็อก และคอนโซล เอาต์พุตของบรรทัดคำสั่ง รูปแบบไฟล์ (`prefs.json` ไฟล์ประวัติ
  พิมพ์เขียว) ข้อมูลเกม (ชื่อพรีแฟบ ไอเทม และชิ้นส่วน คีย์ข้อมูลของวัตถุ) ชื่อ
  ผลิตภัณฑ์และม็อด ในข้อความ (Valheim, Homestead, Steam) และข้อความของ exception (ประโยค
  ที่ล้อมรอบ ได้รับการแปล)
- ขั้นตอนของ Claude ใน ประวัติ ขึ้นต้นด้วยเครื่องหมาย `Claude: ` (`ClaudeTools.ClaudesStep`) ซึ่ง
  คงเป็นภาษาอังกฤษ: ย้อนการเปลี่ยนแปลงของ Claude หาขั้นตอนของ Claude ได้จากเครื่องหมายนี้ คำที่ตามมา
  ได้รับการแปล
- ข้อความที่แสดงต่อผู้ใช้ และ Claude ได้รับด้วย มีทั้งสองแบบ: ภาษาของผู้ใช้จาก `Lang.T`
  และภาษาอังกฤษของ Claude จาก `Lang.En` (`PieceCost.Describe(english: true)`)
- ข้อความบนแถบสถานะ Claude จะอ่านกลับ ใส่ข้อความด้วย `Msg("area.msg.applied", n)`
  หรือ `Msg(said)` พร้อม `Said` (`Said.Of(key, values…)` หรือ `Said.Raw(text)` สำหรับข้อความที่เหมือนกัน
  ทั้งสองภาษา และ `+` เพื่อเพิ่มประโยค): หน้าต่างแสดงภาษาของผู้ใช้ และเก็บภาษาอังกฤษไว้ ซึ่ง
  คำตอบของ Claude อ่าน (`MainWindow.LastMessageEn`) ถ้าจะเพิ่มต่อข้อความล่าสุด ให้ใช้
  `LastSaid + …` ห้ามอ่านจาก `MessageText.Text`
- ตัวเลือกในรายการ ที่จดจำไว้ (`Prefs.Bind`) เก็บเป็นภาษาอังกฤษ จึงกลับมาได้ในทุกภาษา

### การตรวจหน้าต่าง

การทดสอบมีภาษาสมมติ `PseudoLang` ที่ครอบทุกข้อความของแคตตาล็อก เป็น `⟦…⟧`
`PseudoLang.Untranslated(window)` แสดงรายการข้อความ ที่หน้าต่างแสดงนอก `⟦⟧` คือข้อความที่ไม่ได้มาจาก
แคตตาล็อก แต่ละหน้าต่าง มีการทดสอบ `<Window>LangTests` ที่สร้างหน้าต่าง ภายใต้ภาษานั้น และ
คาดว่าจะไม่มีเลย การทดสอบเหล่านี้ รันในคอลเลกชัน `DataDir` เพราะภาษาใช้ร่วมกัน
