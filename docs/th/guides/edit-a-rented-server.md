# แก้ไขเซิร์ฟเวอร์ที่เช่า หรือโฮสต์ผ่านแผงควบคุม

แก้ไขโลกของเซิร์ฟเวอร์ ที่คุณเช่าจากผู้ให้บริการเกม หรือเซิร์ฟเวอร์ที่แผงควบคุมเกม เช่น Pterodactyl หรือ Pelican
รันอยู่ในคอนเทนเนอร์ บนเครื่องของคุณเอง

**การแก้ไขแบบไลฟ์ ต้องเข้าถึงเครื่องที่รันเซิร์ฟเวอร์ ผ่าน SSH ได้**: คือล็อกอินเข้าเชลล์ของเครื่อง ไม่ใช่แค่ SFTP
หรือตัวจัดการไฟล์ เอดิเตอร์เข้าถึงปลั๊กอินผ่าน SSH ที่ `127.0.0.1` ของเซิร์ฟเวอร์เอง (ดู
[แก้ไขเซิร์ฟเวอร์เฉพาะ ขณะที่มีคนเล่น](edit-a-server-live.md)) ก่อนเช่าเซิร์ฟเวอร์ เพื่อแก้ไขแบบไลฟ์
ให้ถามผู้ให้บริการว่า แพ็กเกจรวมการเข้าถึง SSH หรือไม่ เซิร์ฟเวอร์สองแบบนี้ ไม่ตรงกับเงื่อนไขนั้น:

- **เซิร์ฟเวอร์เกม ที่เช่าจากผู้ให้บริการ** (คุณได้แผงควบคุมบนเว็บ และตัวจัดการไฟล์ หรือ FTP/SFTP
  แต่เข้าเครื่องผ่าน SSH ไม่ได้): เอดิเตอร์เข้าถึงปลั๊กอินที่นั่นไม่ได้ ให้แก้ไขไฟล์ของโลกแทน: ดู
  [เซิร์ฟเวอร์เกมที่เช่า](#เซรฟเวอรเกมทเชา)
- **แผงควบคุมเกม บนเครื่องของคุณเอง** (Pterodactyl, Pelican หรือเซิร์ฟเวอร์ใดๆ ที่รันในคอนเทนเนอร์ Docker):
  การแก้ไขแบบไลฟ์ใช้ได้ ผ่านทันเนลที่คุณเปิดเอง ดู [เซิร์ฟเวอร์ในคอนเทนเนอร์](#เซรฟเวอรในคอนเทนเนอร)

หากผู้ให้บริการ ให้ล็อกอิน SSH จริง เข้าเครื่องที่รันเกม (VPS ที่เช่า หรือเครื่องเฉพาะ ไม่ใช่แค่เซิร์ฟเวอร์เกม)
ให้ทำตาม [แก้ไขเซิร์ฟเวอร์เฉพาะ ขณะที่มีคนเล่น](edit-a-server-live.md) แทน

## เซิร์ฟเวอร์เกมที่เช่า

**สิ่งที่ต้องมี:** แผงควบคุม หรือการเข้าถึงไฟล์ของผู้ให้บริการ (ตัวจัดการไฟล์ FTP หรือ SFTP)
และสิทธิ์หยุดและเริ่มเซิร์ฟเวอร์

ใช้โหมดไลฟ์ไม่ได้: ปลั๊กอินตอบเฉพาะบนตัวเครื่องเอง และผู้ให้บริการ ไม่มีทางให้เข้าถึง ล็อกอิน SFTP
ของแผงควบคุม (มักใช้พอร์ต 2022) ให้แค่ไฟล์: SSH ของเอดิเตอร์ เปิดทันเนลผ่านทางนั้นไม่ได้
ให้แก้ไขโลกที่บันทึกไว้แทน:

1. ในแผงควบคุมของผู้ให้บริการ **หยุด** เซิร์ฟเวอร์ เซิร์ฟเวอร์ที่รันอยู่ จะบันทึกทับไฟล์ที่คุณนำกลับไปใส่
2. ใช้ตัวจัดการไฟล์ของแผงควบคุม หรือโปรแกรม SFTP (FileZilla, WinSCP) ดาวน์โหลดโฟลเดอร์ของโลก
   `worlds_local/<World>` ในโฟลเดอร์เซฟของเซิร์ฟเวอร์ เก็บสำเนาไว้หนึ่งชุด โดยไม่แตะต้อง: นั่นคือข้อมูลสำรองของคุณ
3. ในเอดิเตอร์ เปิดโฟลเดอร์นั้น: **โลกที่บันทึกไว้** → **โฟลเดอร์โลกอื่น** → **เรียกดู…** (ดู
   [เปิดโลกที่ไม่อยู่ในรายการ](open-a-world.md))
4. แก้ไขตามต้องการ แล้วกด **บันทึกลงโลก**
5. อัปโหลดโฟลเดอร์กลับไปที่เดิม แทนที่ไฟล์ที่อยู่ตรงนั้น แล้วเริ่มเซิร์ฟเวอร์

เซิร์ฟเวอร์ต้องหยุดอยู่ ตั้งแต่ขั้นตอนที่ 1 ถึงขั้นตอนที่ 5: สิ่งที่ผู้เล่นทำในระหว่างนั้น จะหายไปเมื่อคุณอัปโหลด

## เซิร์ฟเวอร์ในคอนเทนเนอร์

**สิ่งที่ต้องมี:** ล็อกอิน SSH เข้าเครื่องที่รันแผงควบคุม (VPS ของคุณ ในฐานะ root หรือผู้ใช้ที่รัน `docker` ได้)
และสิทธิ์แก้ไขไฟล์ ของเซิร์ฟเวอร์เกม ในแผงควบคุม

แผงควบคุมรัน เซิร์ฟเวอร์เกมแต่ละตัว ในคอนเทนเนอร์ Docker ของตัวเอง ซึ่งมี `127.0.0.1` ของตัวเอง
ปลั๊กอินรอฟังอยู่ที่นั่น ภายในคอนเทนเนอร์ ส่วนทันเนลของเอดิเตอร์ ไปถึง `127.0.0.1` ของตัวเครื่อง
ซึ่งไม่มีอะไรตอบ: เอดิเตอร์จึงบอกว่าปลั๊กอินไม่ตอบ ทั้งที่เซิร์ฟเวอร์รันพร้อมปลั๊กอินอยู่
ทางเข้าคือทันเนล ไปยังที่อยู่ของคอนเทนเนอร์เอง:

```text
 your computer               your VPS          the server's container
┌───────────────────────┐   ┌───────────┐     ┌───────────────────────┐
│ editor                │SSH│           │     │ WorldEditorBridge     │
│ 127.0.0.1:15182 ══════╪═══╪═► sshd ───┼────►│ 172.18.0.x:5182       │
└───────────────────────┘   └───────────┘     └───────────────────────┘
```

1. ในแผงควบคุม ติดตั้ง BepInEx และ WorldEditorBridge ในเซิร์ฟเวอร์ เหมือนเซิร์ฟเวอร์เฉพาะทั่วไป
   (ขั้นตอนที่ 1 ถึง 3 ของ [แก้ไขเซิร์ฟเวอร์เฉพาะ ขณะที่มีคนเล่น](edit-a-server-live.md)) แล้วเริ่มเซิร์ฟเวอร์หนึ่งครั้ง
2. ในตัวจัดการไฟล์ของแผงควบคุม เปิด `BepInEx/config/Tie.WorldEditorBridge.cfg` ตั้ง `BindAddress = +`
   แล้วคัดลอกค่าของบรรทัด `Token`
3. รีสตาร์ตเซิร์ฟเวอร์ คอนโซลหรือ `BepInEx/LogOutput.log` จะแสดง `WorldEditorBridge <version> listening on
   http://+:5182/` ตามด้วยคำเตือนว่า โทเค็นเดินทางโดยไม่เข้ารหัส: ภายในคอนเทนเนอร์ นั่นเป็นแค่เครือข่าย
   ของแผงควบคุมเอง
4. ล็อกอินเข้า VPS ผ่าน SSH แล้วหาที่อยู่ของคอนเทนเนอร์ คอนเทนเนอร์ตั้งชื่อตาม ID ของเซิร์ฟเวอร์
   (แผงควบคุมแสดงไว้ ในการตั้งค่าของเซิร์ฟเวอร์) `docker ps` แสดงรายการทั้งหมด:

   ```sh
   docker inspect -f '{{range .NetworkSettings.Networks}}{{.IPAddress}}{{end}}' <server id>
   ```

   คำสั่งจะตอบเป็นที่อยู่ เช่น `172.18.0.5`
5. บนคอมพิวเตอร์ของคุณ เปิดทันเนลไปยังที่อยู่นั้น และเปิดค้างไว้ระหว่างแก้ไข (แทนที่ที่อยู่และล็อกอิน):

   ```sh
   ssh -N -L 15182:172.18.0.5:5182 user@your-vps
   ```

   ด้วย PuTTY: **Connection** → **SSH** → **Tunnels** ตั้ง **Source port** `15182` **Destination** `172.18.0.5:5182`
   กด **Add** แล้วเปิดเซสชัน
6. ที่หน้าเริ่มต้นของเอดิเตอร์: **เซิร์ฟเวอร์เฉพาะ** → **ตัวเลือกเพิ่มเติม** → **ฉันสร้างทันเนลเอง** พิมพ์
   `127.0.0.1:15182` เป็น **ที่อยู่บริดจ์** วางโทเค็น แล้วกด **เชื่อมต่อ**

จากนั้นแก้ไขเหมือนเซิร์ฟเวอร์อื่นๆ: ดู [โหมดไลฟ์](../live-mode.md#ใชงาน)

**ข้อควรจำ:**

- ใช้ `+` ไม่ใช่ที่อยู่ของคอนเทนเนอร์ และไม่ใช่ `0.0.0.0`: หากใช้ที่อยู่ของคอนเทนเนอร์ ปลั๊กอินจะปฏิเสธ
  ทุกคำขอที่มาผ่านทันเนล และหากใช้ `0.0.0.0` จะปฏิเสธทุกคำขอ ("The server answered with an error (400)" เซิร์ฟเวอร์ตอบกลับ ด้วยข้อผิดพลาด)
- อย่าเพิ่มพอร์ตของปลั๊กอิน (5182) ลงในพอร์ตของเซิร์ฟเวอร์ (allocations) ในแผงควบคุม: การทำเช่นนั้น
  จะเปิดพอร์ตสู่อินเทอร์เน็ต
- ที่อยู่ของคอนเทนเนอร์ อาจเปลี่ยน เมื่อสร้างเซิร์ฟเวอร์ใหม่ หรือติดตั้งใหม่ หากทันเนลหยุดตอบ ให้หาที่อยู่อีกครั้ง
  (ขั้นตอนที่ 4)
- ใช้ `BindAddress = 127.0.0.1` ต่อไป บนเซิร์ฟเวอร์ ที่ไม่ได้รันในคอนเทนเนอร์: ที่นั่น `+` ทำให้ปลั๊กอิน
  รอฟังบนทุกเครือข่าย ที่เครื่องเชื่อมต่ออยู่ (ผู้เรียกจากอินเทอร์เน็ต ยังคงถูกปฏิเสธ)

## ตรวจว่าได้ผล

- **เซิร์ฟเวอร์เกมที่เช่า:** เซิร์ฟเวอร์เริ่มทำงาน และการเปลี่ยนแปลงของคุณ ปรากฏในเกม
- **เซิร์ฟเวอร์ในคอนเทนเนอร์:** แถบด้านบนแสดง **ไลฟ์** และหลัง **นำไปใช้แบบไลฟ์** จะแสดง "นำไปใช้ทั้งหมดแล้ว"

หากเอดิเตอร์แสดงข้อความแทน ดู [เซิร์ฟเวอร์เชื่อมต่อไม่ได้](../help/troubleshooting.md#เซรฟเวอรเชอมตอไมได)

## เลิกทำ

- **เซิร์ฟเวอร์เกมที่เช่า:** หยุดเซิร์ฟเวอร์ แล้วอัปโหลดสำเนา ที่เก็บไว้ในขั้นตอนที่ 2
- **เซิร์ฟเวอร์ในคอนเทนเนอร์:** `Ctrl+Z` แล้วกด **นำไปใช้แบบไลฟ์** อีกครั้ง หากต้องการปิดปลั๊กอินอีกครั้ง
  ตั้ง `BindAddress =
  127.0.0.1` แล้วรีสตาร์ตเซิร์ฟเวอร์
