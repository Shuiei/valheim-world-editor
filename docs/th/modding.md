# สำหรับผู้สร้างม็อด

เอดิเตอร์ทำงานกับม็อดก่อสร้างได้ โดยไม่ต้องมีอะไรจากผู้สร้างม็อด: เมื่อเชื่อมต่อกับเกม ที่ติดตั้งม็อด
เอดิเตอร์จะเรียนรู้วัตถุของม็อด วาดด้วยโมเดลของม็อดเอง และตั้งชื่อข้อมูล ที่ม็อดเก็บไว้
หน้านี้สำหรับผู้สร้างม็อด ที่ต้องการมากกว่านั้น: ไฟล์ `worldeditor.json` ที่ไม่บังคับ สำหรับสิ่งที่เอดิเตอร์
เดาไม่ได้ **วัตถุที่เชื่อมโยง** สำหรับม็อดที่สร้างสิ่งหนึ่ง จากวัตถุหลายชิ้น **ส่วนขยาย
เอดิเตอร์** (DLL เล็กๆ ที่บิลด์กับ SDK ของเอดิเตอร์) สำหรับสิ่งที่ไฟล์บอกไม่ได้ **แอดออน**
(แบบเดียวกัน แต่ใครก็ทำได้ สำหรับม็อดของคนอื่น) และ **ฮุกของบริดจ์** ให้ปลั๊กอินของม็อดเอง
มีส่วนร่วมในโหมดไลฟ์

ทุกอย่างในหน้านี้ ไม่บังคับ และแต่ละขั้น ต่อยอดจากขั้นก่อนหน้า เอดิเตอร์ไม่ได้มาพร้อมสิ่งใด สำหรับม็อดใด
การรองรับม็อดในเอดิเตอร์ เป็นงานของผู้สร้างม็อด ด้วยเครื่องมือเหล่านี้ ตัวอย่างในหน้านี้
เป็นของม็อดสมมติ "Example Vehicles" ซึ่งตัวอย่างฉบับเต็ม มาพร้อมกับ SDK (ดู
[ตัวอย่าง Example Vehicles](#ตวอยาง-example-vehicles))

## สิ่งที่เอดิเตอร์เรียนรู้ได้เอง

| อะไร | เอดิเตอร์เรียนรู้อย่างไร |
|---|---|
| วัตถุของม็อด: ชื่อ ชิ้นส่วนก่อสร้าง ค่าใช้จ่าย สถานีคราฟต์ และเครื่องมือที่ใช้สร้างแต่ละชิ้น | เมื่อเชื่อมต่อกับเกม (โหมดไลฟ์ WorldEditorBridge 1.26.0 ขึ้นไป) เอดิเตอร์จะถามเกม ถึงทุกวัตถุที่เกมรู้จัก และเก็บวัตถุ ที่ไม่ใช่ของ Valheim เอง ไว้ใน `mod-catalogue.json` ในโฟลเดอร์ข้อมูลของเอดิเตอร์ โลกของเซิร์ฟเวอร์ที่ติดตั้งม็อด ที่เปิดจากไฟล์ภายหลังแบบออฟไลน์ จึงแสดงวัตถุเหล่านั้นด้วย รายงานชิ้นส่วนที่ใหม่กว่า ของม็อดหนึ่ง จะแทนที่รายงานเก่า ม็อดไม่เคยเปลี่ยนวัตถุ ของ Valheim เอง |
| หน้าตา | เกมบอกว่าวาดอะไร สำหรับวัตถุของม็อดแต่ละชิ้น (WorldEditorBridge 1.27.0 ขึ้นไป) เอดิเตอร์หาเมช วัสดุ และเท็กซ์เจอร์เหล่านั้น ในไฟล์ของม็อดเอง บนคอมพิวเตอร์ของผู้เล่น (asset bundle ของม็อด ที่คัดลอกออกจาก DLL ครั้งเดียว ไปไว้ใน `mod-bundles` ในโฟลเดอร์ข้อมูล) เมชที่ม็อดสร้างในโค้ด ขณะที่เกมรัน หาไม่ได้: วัตถุเหล่านั้นจะแสดง โดยไม่มีพื้นผิว เว้นแต่ [ส่วนขยาย](#สวนขยาย) จะวาดให้ |
| ชื่อของข้อมูล ที่ม็อดเก็บไว้บนวัตถุ | เกมบันทึกเพียงแฮช ของคีย์ข้อมูลแต่ละตัว เอดิเตอร์หาชื่อ จากข้อความที่เขียนอยู่ใน DLL ของม็อด (อ่านเป็นไบต์ ไม่เคยรัน) ในโฟลเดอร์ปลั๊กอิน ที่รู้จัก และเก็บไว้ใน `mod-zdo-keys.json` จนกว่า DLL จะเปลี่ยน คีย์ที่ชื่อถูกประกอบขึ้น ขณะที่เกมรัน (`"Corner" + i`) หาด้วยวิธีนี้ไม่ได้: ตั้งชื่อไว้ใต้ `data` ใน `worldeditor.json` ของคุณ (ด้านล่าง) มิฉะนั้น ตัวตรวจดูข้อมูล จะแสดงเป็น `#` ตามด้วยแฮช |
| วัตถุมาจากม็อดใด | ตัวตรวจดูข้อมูล จะบอก (เมื่อติดตั้ง Jötunn ซึ่งรู้ข้อมูลนี้ มิฉะนั้น "จากม็อด") แผง [ก่อสร้าง](build.md) ทั้งในโลก และในเวิร์กช็อป แสดงชิ้นส่วนของม็อด บนแท็บ **ชิ้นส่วนม็อด** ทีละม็อด |

ดู [เกมที่ติดตั้งม็อด](live-mode.md#เกมทตดตงมอด) สำหรับฝั่งผู้เล่น

## worldeditor.json

มีบางอย่าง ที่เอดิเตอร์เดาไม่ได้ ม็อดบอกได้ ในไฟล์ `worldeditor.json` ที่ส่งไปพร้อม
ม็อด ที่ใดก็ได้ในโฟลเดอร์ของม็อด ใต้ `BepInEx/plugins` (ข้าง DLL ก็ได้) นี่คือไฟล์ของ Example
Vehicles:

```json
{
  "$schema": "https://raw.githubusercontent.com/Shuiei/valheim-world-editor/main/docs/worldeditor.schema.json",
  "version": 1,
  "extension": "ExampleVehicles.WorldEditor.dll",
  "gameComponents": ["Ship"],
  "data": {
    "ExampleVehicles_Vehicle": { "label": "Vehicle", "readOnly": true, "help": "The vehicle this part is built on." },
    "ExampleVehicles_Offset": { "label": "Place on the vehicle", "readOnly": true },
    "ExampleVehicles_Packed": { "label": "Linked objects", "help": "The objects this one is tied to." }
  },
  "prefabs": {
    "example_boundary": { "hidden": true },
    "example_fleet": { "hidden": true, "data": true },
    "example_canal": { "hidden": true, "data": true },
    "example_hull": { "group": "Hulls" },
    "example_sail": { "group": "Sails and cables" },
    "example_post": { "group": "Sails and cables" },
    "example_pit": { "group": "Digging" }
  }
}
```

| คีย์ | สิ่งที่เอดิเตอร์ทำกับคีย์นี้ |
|---|---|
| `version` | เวอร์ชันของรูปแบบ: `1` ไฟล์ที่เป็นเวอร์ชันใหม่กว่า หรือไม่มีเวอร์ชัน จะถูกข้ามทั้งไฟล์ |
| `data` | ตามคีย์ข้อมูล ตามที่โค้ดของคุณตั้งชื่อ (ชื่อที่เกมบันทึกแฮชไว้ คีย์ที่ตั้งชื่อที่นี่ จะรู้จักด้วยชื่อ แม้ DLL ของคุณ จะไม่มีชื่อนั้นเป็นข้อความ): `label` ชื่อที่ [ตัวตรวจดูข้อมูล](select.md#ตวตรวจดขอมล) ใช้เรียกค่านั้น (มิฉะนั้น ใช้คีย์ ชื่อของเอดิเตอร์เอง สำหรับคีย์ของเกม มาก่อน) `readOnly` ตัวตรวจดูข้อมูล แสดงค่า แต่ไม่ให้เปลี่ยน (ค่าที่ม็อดตั้งเอง และจะเสียหาย ถ้าถูกแก้) `help` อธิบายว่าค่าคืออะไร แสดงเมื่อชี้ที่ค่านั้น |
| `prefabs` | ตามชื่อพรีแฟบ: `hidden` ไม่แสดงในรายการของ [จัดวาง](place.md) หรือแผง [ก่อสร้าง](build.md) (เครื่องมือ เอฟเฟกต์ ตัวช่วยของคุณ วัตถุชนิดนี้ ที่อยู่ในโลกแล้ว ยังแสดงอยู่) `group` หัวข้อ ที่ชิ้นส่วนของคุณแสดงอยู่ใต้ ในแท็บ **ชิ้นส่วนม็อด** ของแผง ก่อสร้าง ต่อจากชื่อม็อด ("*ชื่อม็อด* · Hulls") เมื่อไม่มี group ชิ้นส่วนจะแสดงใต้สถานีคราฟต์ มิฉะนั้น ใต้ "ไม่ต้องใช้สถานีคราฟต์" `group` มีผลเฉพาะกับชิ้นส่วน ของม็อดเอง `data`: วัตถุชนิดนี้ เก็บแค่ข้อมูลของม็อดคุณ (ทะเบียน สิ่งที่ขุดในพื้นที่) และไม่มีอะไรให้เห็น: เอดิเตอร์ไม่เคยวาด เลือก หรือแสดงรายการ วัตถุเหล่านี้ในพื้นที่ (ส่วนขยายของคุณ ยังอ่านได้) และ [การรีเซ็ตโซน](area.md) จะเก็บไว้ เมื่อเก็บสิ่งก่อสร้าง และลบไปพร้อมทุกอย่าง ในกรณีอื่น `piece`: ชิ้นส่วนก่อสร้าง ที่ม็อดของคุณสร้างในโค้ด ซึ่งไม่มีบันเดิลใดเก็บไว้: `{ "name": "Track 2 m", "cost": { "Stone": 4 }, "station": "Stonecutter" }` (ต้องมี `name` ไม่เกิน 64 ตัวอักษร `cost` ตามชื่อพรีแฟบของไอเทม ไม่เกิน 16 ไอเทม `station` ตามชื่อภาษาอังกฤษ) แท็บ **ชิ้นส่วนม็อด** ของแผง ก่อสร้าง จะแสดงชิ้นส่วนนี้ ใต้ม็อดของคุณ แม้ไม่มีเกมไลฟ์ (ข้อมูลจากเกมไลฟ์ มีลำดับสูงกว่า) ชิ้นส่วนในบันเดิลของคุณ ไม่ต้องใช้คีย์นี้: เอดิเตอร์หาได้จาก `Piece` หรือจากจุดสแนป เมื่อคุณเพิ่ม `Piece` ในโค้ด |
| `links` | วิธีที่วัตถุของคุณ เชื่อมโยงเป็นหนึ่งเดียว: ดู [วัตถุที่เชื่อมโยง](#วตถทเชอมโยง) |
| `ties` | วิธีที่วัตถุของคุณ ผูกกับวัตถุที่ระบุถึงวัตถุเหล่านั้น (ตู้ของรถไฟ): ดู [วัตถุที่ผูกกัน](#วตถทผกกน) |
| `extension` | DLL ส่วนขยายเอดิเตอร์ของคุณ เทียบกับโฟลเดอร์ของไฟล์ และต้องอยู่ในโฟลเดอร์นั้น: ดู [ส่วนขยาย](#สวนขยาย) |
| `gameComponents` | ชื่อคลาสของสคริปต์ของเกมเอง ที่ส่วนขยายของคุณ ต้องใช้ฟิลด์ (`"TerrainOp"`, `"Ship"` ไม่เกิน 32): ขณะที่ส่วนขยายของคุณทำงาน เอดิเตอร์จะอ่านทุกคอมโพเนนต์ ของคลาสเหล่านั้น ในพรีแฟบของเกม จาก Valheim ของผู้เล่น (ครั้งเดียว แล้วเก็บไว้ จนกว่าเกมจะเปลี่ยน) และส่งให้เป็น `Host.Game` (ดู [ฮุก](#ฮก)) |
| `settingsFiles` | ชื่อไฟล์การตั้งค่า BepInEx ของม็อดคุณ ที่ส่วนขยายอ่าน (`"author.mod.cfg"` ใน `BepInEx/config` ไม่เกิน 8): เมื่อเปิดโลก เอดิเตอร์อ่านไฟล์เหล่านั้น จากโฟลเดอร์ BepInEx แรกของผู้เล่น ที่มีไฟล์นั้น และในโหมดไลฟ์ อ่านจากเกมที่เชื่อมต่อ ผ่านบริดจ์ของเกม (ของเซิร์ฟเวอร์ ซึ่งผู้เล่นได้รับการตั้งค่า ที่ซิงก์มา) ส่วนขยายของคุณ อ่านการตั้งค่าหนึ่งค่า ด้วย `Host.Setting(file, section, key)` (ดู [ฮุก](#ฮก)) |
| `worldGenerators` | ตัวสร้างโลก ที่ส่วนขยายของคุณลงทะเบียน (ดู [ตัวสร้างโลก](#ตวสรางโลก)) ตาม id ที่ไฟล์ของโลกระบุ แต่ละตัว พร้อมชื่อม็อดของคุณ สำหรับผู้เล่น: `{ "author.mod": "Some Mod" }` (ไม่เกิน 8) เอดิเตอร์อ่านคีย์นี้ แม้ส่วนขยายของคุณ ไม่ได้ทำงาน เพื่อให้โลกที่ม็อดของคุณสร้าง บอกได้ว่าทำไมเปิดไม่ได้: แอดออนปิดอยู่ รอม็อดของคุณ ไม่ทำงาน หรือส่วนขยายของม็อดคุณ ยังไม่ได้เปิด |

### วิธีที่เอดิเตอร์อ่านไฟล์

- **ที่ไหน** ในทุกโฟลเดอร์ `plugins` ที่เอดิเตอร์รู้จัก: `BepInEx` ของโฟลเดอร์ Valheim โปรไฟล์
  ตัวจัดการม็อด ที่ติดตั้งเอดิเตอร์ไว้ โฟลเดอร์ที่เพิ่มใน **การตั้งค่า → โฟลเดอร์ BepInEx**
  และทุกโปรไฟล์ของ r2modman และ Thunderstore Mod Manager ทุกไฟล์ที่ชื่อ
  `worldeditor.json` ในนั้น นับทั้งหมด ไม่ว่าจะลึกเท่าใด
- **เมื่อไร** ทุกครั้งที่เปิดโลก หรือเวิร์กช็อป และเมื่อเปิด **การตั้งค่า** ไฟล์ที่เปลี่ยน
  ขณะที่โลกเปิดอยู่ จะมีผลในครั้งถัดไป
- **ม็อดใด** ไฟล์เป็นของม็อด ที่โฟลเดอร์อยู่ใต้ `plugins` โดยตรง (
  `ExampleVehicles` ของ `plugins/ExampleVehicles/worldeditor.json`) การตั้งค่า ใช้ชื่อนี้เรียกส่วนขยาย
- **สองไฟล์ ชื่อเดียวกัน** ไฟล์จะถูกอ่าน จากเก่าสุดก่อน (ตามเวลาที่เปลี่ยนครั้งล่าสุด): เมื่อ
  สองไฟล์ ระบุถึงคีย์ข้อมูล พรีแฟบ หรือ `id` ของลิงก์เดียวกัน ไฟล์ที่ใหม่สุดจะชนะ
- **ผ่อนปรน** อนุญาตคอมเมนต์ และจุลภาคท้าย ข้อความยาว 1 ถึง 200 ตัวอักษร รายการ
  มีได้ไม่เกิน 32 ชื่อ ไฟล์มีขนาดไม่เกิน 1 MB รายการที่ไม่อยู่ในรูปแบบนี้ จะถูกข้าม และส่วนที่เหลือ
  ของไฟล์ ยังมีผล ไฟล์ที่ไม่ใช่ JSON หรือไม่ใช่เวอร์ชัน ที่เอดิเตอร์อ่านได้ จะถูก
  ข้าม ล็อกของเอดิเตอร์จะแจ้งไว้ ("mod manifest …: not a worldeditor.json this editor reads,
  skipped." ไม่ใช่ worldeditor.json ที่เอดิเตอร์นี้อ่านได้ จึงข้ามไป)

[สคีมา](../worldeditor.schema.json) อธิบายไฟล์: เมื่อมีบรรทัด `$schema` ด้านบน โปรแกรมแก้ไขโค้ด
จะตรวจไฟล์ และเติมคีย์ให้ ขณะที่คุณพิมพ์

## วัตถุที่เชื่อมโยง

ถ้าม็อดของคุณ สร้างวัตถุจากวัตถุอื่น (เรือ และชิ้นส่วนที่สร้างบนเรือ เกวียน และของที่บรรทุก)
เกมจะบันทึกแต่ละชิ้นแยกกัน และเอดิเตอร์จะเห็น ชิ้นส่วนกระจัดกระจาย กองอยู่ตรงที่เกมบันทึกไว้
บอกเอดิเตอร์ ว่าเชื่อมโยงกันอย่างไร แล้วเอดิเตอร์จะวาด แบบที่ม็อดของคุณสร้าง และย้าย คัดลอก และลบแต่ละ
กลุ่มทั้งกลุ่ม (ดู [วัตถุที่เชื่อมโยง](select.md#เรอและวตถอนทเชอมกน) สำหรับสิ่งที่
ผู้เล่นเห็น) วิธีนี้ใช้ได้กับม็อด ที่เชื่อมโยงแบบทั่วไป: ราก (และส่วนใดก็ตาม ที่ส่วนอื่นแขวนอยู่
บนนั้น) เก็บ id แบบ int ของตัวเอง แต่ละส่วนเก็บ id ของสิ่งที่ตนแขวนอยู่ไว้ในข้อมูล พร้อม
ออฟเซ็ต และการหมุน ในเฟรมของสิ่งนั้น

```json
{
  "version": 1,
  "links": [
    {
      "name": "vehicle",
      "id": "ExampleVehicles_Id",
      "parents": ["ExampleVehicles_Mount", "ExampleVehicles_Vehicle"],
      "offset": "ExampleVehicles_Offset",
      "rotation": "ExampleVehicles_Turn",
      "rotationQuaternion": "ExampleVehicles_TurnQ",
      "storedAt": "root",
      "references": ["ExampleVehicles_Target", "ExampleVehicles_Drives"],
      "dropOnCopy": ["ExampleVehicles_Packed", "ExampleVehicles_Aboard"]
    }
  ]
}
```

| คีย์ | |
|---|---|
| `id` | คีย์ข้อมูลแบบ int ของ id ของวัตถุเอง ที่ส่วนต่างๆ ระบุถึง จำเป็น |
| `parents` | คีย์ข้อมูลแบบ int ที่ระบุสิ่งที่ส่วนหนึ่งแขวนอยู่ ตัวแรกที่มีค่า จะชนะ (ชิ้นส่วนบนแท่นหมุน ระบุแท่นหมุน ก่อนยานพาหนะ) อย่างน้อยหนึ่งตัว จำเป็น |
| `offset` | คีย์ข้อมูลแบบ Vec3 ของตำแหน่งของส่วนหนึ่ง ในเฟรมของสิ่งที่แขวนอยู่ หน่วยเมตร จำเป็น |
| `rotation` | คีย์ข้อมูลแบบ Vec3 ของการหมุน ในเฟรมนั้น เป็นมุมออยเลอร์ของ Unity หน่วยองศา |
| `rotationQuaternion` | คีย์ข้อมูลแบบ Quaternion ของการหมุนนั้น ใช้เมื่อไม่ได้เก็บ `rotation` ไว้ เมื่อไม่มีทั้งสองอย่าง ส่วนนั้นจะไม่หมุน ในเฟรมของพาเรนต์ |
| `storedAt` | ตำแหน่งที่เกมบันทึกส่วนหนึ่ง: `root` (ที่รากของกลุ่ม ม็อดของคุณสร้างจากออฟเซ็ต เมื่อโหลดกลุ่ม ค่าเริ่มต้น) หรือ `own` (ตรงที่ตั้งอยู่) เอดิเตอร์บันทึกส่วนที่ย้าย แบบเดียวกัน |
| `references` | คีย์ข้อมูลแบบ int อื่นๆ ที่ระบุ id ของวัตถุ (เสากระโดงของใบเรือ เป้าหมายของสวิตช์): ในสำเนาที่วาง ค่าเหล่านี้จะตาม id ใหม่ของสำเนา และถูกนำออก เมื่อสิ่งที่ระบุถึง ไม่ได้ถูกคัดลอก |
| `dropOnCopy` | คีย์ข้อมูล ที่สำเนาที่วางจะไม่มี: id ที่แพ็กไว้ ในแบบที่เอดิเตอร์เขียนใหม่ไม่ได้ (ไบต์อาร์เรย์) การผูก ที่ต้องไม่ติดไปด้วย (สิ่งที่อยู่บนยาน) |
| `placements` | ตามคีย์พาเรนต์ (หนึ่งใน `parents`) วิธีวางส่วนที่แขวนอยู่ เมื่อไม่ได้วางตามกฎ: คีย์ `offset` `rotation` และ `rotationQuaternion` ของตัวเอง และ `storedAt` (ตัวที่ไม่ได้ให้ไว้ ใช้ของกฎ) เช่น ใบเรือ ที่เก็บตำแหน่งบนเสากระโดง แยกจากตำแหน่งบนเรือ หรือ `"carried": true` (และไม่มีคีย์เหล่านั้น) ส่วนที่กลุ่มบรรทุกไว้ ตรงที่เกมบันทึก (เกวียนบนเรือ): ไม่มีออฟเซ็ต วาดตรงที่บันทึกไว้ เทียบกับสิ่งที่บรรทุก และย้าย หมุน คัดลอก และลบ พร้อมกลุ่ม และบันทึกตรงที่ตั้งอยู่ |
| `name` | ชื่อเรียกกลุ่มหนึ่ง ในข้อความของเอดิเตอร์ ("ทั้ง vehicle") ค่าเริ่มต้น: `group` |

### วิธีที่เอดิเตอร์ใช้การเชื่อมโยง

- **การวาด** ส่วนหนึ่ง วาดที่ออฟเซ็ต ในเฟรมของพาเรนต์ พาเรนต์อยู่ตรงที่พาเรนต์ของมัน
  วางไว้ ต่อขึ้นไปเรื่อยๆ จนถึงราก ซึ่งตั้งอยู่ตรงที่บันทึกไว้: ชิ้นส่วนของเรือ หมุนและเอียง
  ไปกับตัวเรือ ส่วนที่ถูกบรรทุก อยู่ตรงที่บันทึกไว้ เทียบกับสิ่งที่บรรทุก ส่วนขยาย
  หมุนเฟรมที่ส่วนต่างๆ ของพาเรนต์แขวนอยู่ หรือวางส่วนเองได้ (`AddLinkPlacer` ดู
  [ฮุก](#ฮก)) ส่วนที่พาเรนต์ (หรือพาเรนต์ใดๆ ในสายขึ้นไป) ไม่อยู่ในโลก หรือที่
  สายวนกลับ หรือลึกเกิน 16 ชั้น (ข้อมูลเสียหาย) จะอยู่ตรงที่บันทึกไว้
- **กฎใด** วัตถุใช้กฎแรก ที่วัตถุมีคีย์ `id` หรือ `parents` ของกฎนั้น ชื่อพรีแฟบ
  ไม่มีผล: มีแค่ข้อมูล กฎของไฟล์ที่ใหม่กว่า ที่มี `id` เดียวกัน จะแทนที่ของ
  ไฟล์เก่า ในตำแหน่งเดิมของลำดับ
- **การย้ายและการลบ** การเลือกส่วนใดก็ได้ แล้วย้าย หมุน หรือลบ จะทำกับทั้ง
  กลุ่ม กลุ่มที่ย้าย คงความสูงไว้ และไม่สแนป ส่วนต่างๆ ถูกบันทึกตามที่ `storedAt` ระบุ
- **การคัดลอก** สำเนาจะรวมทั้งกลุ่ม การวางแต่ละครั้ง (และการวางซ้ำแต่ละครั้ง) ได้ id ใหม่ ที่
  ไม่มีวัตถุใดในโลกมี แม้แต่วัตถุที่ลบไปแล้ว เกมจึงไม่เคยนับสองสำเนา เป็นชิ้นเดียว ทุกค่า
  พาเรนต์ และ `references` จะตามไปด้วย ส่วนที่คัดลอก โดยไม่มีพาเรนต์ จะถูกวางเป็นวัตถุ
  ธรรมดา (ลบการเชื่อมโยงออก) ตรงที่วาง การวางแบบสะท้อน จะสะท้อนออฟเซ็ต และ
  การหมุนของส่วนต่างๆ ด้วย ค่าใน `dropOnCopy` จะหายไป เว้นแต่ตัวเขียนสำเนาใหม่ ของส่วนขยาย จะจัดการให้
- คีย์ข้อมูล ตั้งชื่อตามที่โค้ดของคุณตั้ง เหมือนใน `data`

## วัตถุที่ผูกกัน

ม็อดบางตัว ผูกวัตถุเข้าด้วยกัน โดยไม่เก็บว่าแต่ละชิ้น อยู่ห่างจากกันอย่างไร: รถไฟระบุตู้ ที่ลากไว้
ดาดฟ้า ไม่ระบุอะไรเลย แต่สิ่งที่สร้างบนดาดฟ้า ระบุดาดฟ้า เกมบันทึกแต่ละวัตถุ ตรงที่ตั้งอยู่ และม็อดของคุณ
ประกอบกลับขึ้นมาใหม่ ขณะที่รันอยู่ บอกเอดิเตอร์ว่าผูกกันอย่างไร แล้วเอดิเตอร์จะเก็บไว้ เป็นกลุ่มเดียว:

```json
{
  "version": 1,
  "ties": [
    { "name": "train", "root": "ExampleVehicles_Wagons", "member": "ExampleVehicles_Self", "idBytes": 12 },
    { "name": "deck", "root": "ExampleVehicles_DeckId", "member": "ExampleVehicles_OnDeck" }
  ]
}
```

| คีย์ | |
|---|---|
| `root` | คีย์ข้อมูลของ id ที่รากระบุ: int, long หรือไบต์อาร์เรย์ ที่เก็บหลาย id ต่อกัน จำเป็น |
| `member` | คีย์ข้อมูลของ id ของสมาชิกเอง ชนิดเดียวกัน (int, long หรือไบต์อาร์เรย์) จำเป็น |
| `idBytes` | สำหรับไบต์อาร์เรย์ id หนึ่งตัว ยาวกี่ไบต์ (1 ถึง 64 และ 12 สำหรับ id วัตถุของเกม) เมื่อไม่มีคีย์นี้ ค่าทั้งหมด คือ id เดียว |
| `name` | ชื่อเรียกกลุ่มหนึ่ง ในข้อความของเอดิเตอร์ ค่าเริ่มต้น: `group` |

สมาชิกอยู่ในกลุ่มของราก เมื่อ id ของสมาชิกเอง เป็นหนึ่งใน id ที่รากระบุ id จะถูกเปรียบเทียบ ตามไบต์
ไม่ว่าจะมีความหมายอย่างไร สำหรับม็อดของคุณ: เอดิเตอร์ไม่เคยค้นหา id ในเกม กลุ่มที่มีวัตถุร่วมกัน คือกลุ่ม
เดียวกัน: รถไฟที่ตู้พื้นเรียบ เป็นรากของดาดฟ้า จะพาสิ่งที่สร้างบนดาดฟ้าไปด้วย

- **การเลือก การย้าย และการลบ** การเลือกวัตถุใดก็ได้ของกลุ่ม แล้วย้ายหรือหมุน จะทำกับทั้งกลุ่ม
  เป็นก้อนเดียว: สมาชิกแต่ละตัว คงตำแหน่งเทียบกับตัวอื่นไว้ และถูกบันทึกตรงที่ตั้งอยู่ การลบราก
  จะลบสมาชิกไปด้วย การลบสมาชิก จะลบแค่สมาชิกนั้น
- **การคัดลอก** สำเนาจะรวมทั้งกลุ่ม การวางแต่ละครั้ง (และการวางซ้ำแต่ละครั้ง) ได้ id ใหม่ ชนิดและ
  ขนาดเดียวกัน แบบสุ่ม ทั้งในราก และในสมาชิกที่รากระบุ สำเนาจึงไม่เคยเอา สมาชิกของต้นฉบับไป: รายการจะเก็บ
  id ของสมาชิกที่คัดลอก id เดี่ยว จะเป็นค่าใหม่เสมอ และสมาชิก ที่รากไม่ได้ถูกคัดลอก จะเสีย id ไป
- **ไลฟ์และบันทึก** id ใหม่ เป็นหน้าที่ของม็อดคุณ ที่ต้องจับคู่: ม็อดหาสมาชิกของรากที่วาง จาก id ที่สมาชิกมี เหมือน
  ที่ทำหลังเกมโหลดโลก (เกมให้ id วัตถุใหม่ กับทุกวัตถุ ทุกครั้งที่โหลด)
- กฎที่มีคีย์ `root` และ `member` เดียวกัน ในไฟล์ที่ใหม่กว่า จะแทนที่ของไฟล์เก่า ในตำแหน่งเดิมของลำดับ

## ส่วนขยาย

สิ่งที่ไฟล์บอกไม่ได้ โค้ดบอกได้ ม็อดส่ง **ส่วนขยายเอดิเตอร์** มาด้วยได้: DLL เล็กๆ ที่บิลด์
กับ SDK ของเอดิเตอร์ ซึ่งเอดิเตอร์โหลด เพื่ออ่านและวาดวัตถุของม็อด ส่วนขยายไม่ได้รัน
ในเกม และไม่เคยเห็นโค้ดของเกม หรือของ Unity: เห็นเพียงข้อมูลของวัตถุ ตามที่เอดิเตอร์
มี ส่วนขยายสามารถ:

- แสดงค่าไบต์อาร์เรย์ เป็นคำ ใน ตัวตรวจดูข้อมูล
- เขียน id ที่ม็อดของคุณแพ็กไว้ ในรูปแบบของตัวเอง ใหม่ในสำเนาที่วาง
- ตั้งค่าที่ม็อดของคุณคำนวณ จากตำแหน่งที่วัตถุตั้งอยู่ ทุกครั้งที่เอดิเตอร์ จัดวาง วาง ย้าย หรือหมุนวัตถุนั้น (
  รางใต้ยานพาหนะ การหมุนที่ม็อดของคุณเก็บไว้)
- วาดสิ่งที่ม็อดของคุณสร้างในโค้ด ขณะที่เกมรัน (ใบเรือจากมุมต่างๆ สายเคเบิล จากเสา
  ถึงเสา)
- วางส่วนต่างๆ ของวัตถุที่เชื่อมโยง ตรงที่ม็อดของคุณสร้าง เมื่อข้อมูลอย่างเดียว ไม่ได้
  บอก (ส่วนบนแท่นหมุน ที่ม็อดของคุณหมุนไว้)
- ไม่วาดพื้นดิน ตรงที่ม็อดของคุณขุด (ปากอุโมงค์ หลุม)
- วาดสิ่งที่ม็อดของคุณ ทำกับพื้นที่ทั้งหมด (คลอง หินที่ขุดออกจากเนินเขา) ด้วยรูปลักษณ์พื้นดินของเกม แทน
  พื้นดินของเอดิเตอร์
- อ่านการตั้งค่า ของสคริปต์ของเกมเอง (`gameComponents` ของส่วนขยาย) ตามที่ Valheim ของผู้เล่นมี
- อ่านการตั้งค่า ของม็อดคุณเอง (`settingsFiles` ของส่วนขยาย) ตามที่เกมของโลกมี
- เพิ่มเครื่องมือของคุณเอง ลงในแถบเครื่องมือของเอดิเตอร์ 3D พร้อมการ์ดการตั้งค่า ตัวอย่าง และการแก้ไข
  ในประวัติ (ขุดคลอง ตรงที่ผู้เล่นคลิก)
- สำหรับม็อดสร้างโลก อ่านและวาดโลกที่ม็อดสร้าง และสร้างโลกใหม่ด้วยม็อดนั้น
- ในโหมดไลฟ์ ถามปลั๊กอินของม็อดคุณเอง ในเกม ถึงสิ่งที่มีแค่เกมรู้ (ดู
  [โหมดไลฟ์](#โหมดไลฟ))

   ไปยังเอาต์พุต (`Private="false"`): เอดิเตอร์ให้ของตัวเอง ไม่ใช้อะไรอื่น นอกจาก
   เฟรมเวิร์ก (โปรเจกต์ตัวอย่าง อ้างอิงแพ็กเกจ `System.Numerics.Vectors` ด้วย สำหรับ
   `Vector3` และ `Quaternion`) ส่วนขยายคือ **DLL เดียว**: เอดิเตอร์ไม่โหลดไฟล์อื่น จาก
   โฟลเดอร์ของคุณ ไลบรารีตัวช่วย ที่อยู่ข้างๆ จึงไม่ถูกพบ
3. **ทำเครื่องหมาย assembly** และให้จุดเริ่มต้น: คลาส public ที่มีคอนสตรักเตอร์ ไม่มี
   พารามิเตอร์ และ implement `IWorldEditorExtension` เอดิเตอร์สร้างคลาสนี้ครั้งเดียว และเรียก `Register`
   ครั้งเดียว ก่อนใช้ฮุกใดๆ นี่คือของตัวอย่าง:

   ```csharp
   [assembly: WorldEditorExtension(typeof(ExampleVehicles.WorldEditor.Extension))]

   public sealed class Extension : IWorldEditorExtension
   {
       public void Register(IExtensionRegistry registry)
       {
           var packed = new PackedIds();
           registry.AddDecoder(Keys.Packed, packed);           // inspector
           registry.AddCopyRewriter(packed, Keys.Packed);      // paste
           registry.AddShapes(new Sails(), Keys.Sail);         // 3D view
           registry.AddShapes(new Cables(), Keys.Post);
           registry.AddGroundCuts(new Pits(), Keys.Pit);       // the ground
           registry.AddScene(new Canals());                    // the area as a whole
           registry.AddTool(new CanalTool());                  // a tool on the rail
           registry.AddAreaCopier("canals", new CanalCopies()); // copy and paste
           registry.AddLiveListener(new LiveLink(registry));   // live mode
           registry.Log($"ready (editor {registry.EditorVersion}, API {registry.ApiVersion})");
       }
   }
   ```

4. **ส่งไปพร้อมม็อด** ไว้ในโฟลเดอร์ของม็อด และระบุชื่อใน `worldeditor.json` ของคุณ:
   `"extension": "ExampleVehicles.WorldEditor.dll"` พาธที่ออกนอกโฟลเดอร์ของไฟล์ หรือไฟล์
   ที่ไม่ได้ลงท้ายด้วย `.dll` จะไม่ถูกนำเสนอ

### การเปิดใช้: การตั้งค่า → ส่วนขยายของม็อด

ส่วนขยาย คือโค้ดที่รันในเอดิเตอร์ ด้วยสิทธิ์ของผู้เล่น **ผู้เล่นจึงเป็นผู้ตัดสินใจ**
เอดิเตอร์หาส่วนขยาย ที่ม็อดในโฟลเดอร์ปลั๊กอินนำเสนอ และแสดงรายการไว้ใน
**การตั้งค่า** ใต้ **ส่วนขยายของม็อด**: สวิตช์หนึ่งตัว ต่อส่วนขยายหนึ่งตัว ตั้งชื่อตามโฟลเดอร์ของม็อด และ
ไฟล์ ("ExampleVehicles · ExampleVehicles.WorldEditor.dll") การชี้ที่สวิตช์ จะแสดงพาธของไฟล์ และ
SHA-256 ใต้สวิตช์แต่ละตัว เอดิเตอร์บอกสถานะ: "ทำงานอยู่" "ไม่ทำงาน: …" พร้อม
เหตุผล หรือ "ปิดอยู่: the file cannot be read" (อ่านไฟล์ไม่ได้) เมื่อไม่มีม็อดใดนำเสนอ: "ไม่มีม็อดในโฟลเดอร์ด้านบน
ที่มีส่วนขยาย"

- **ปิดไว้โดยค่าเริ่มต้น** ส่วนขยายจะทำงาน เมื่อผู้เล่นเปิด และกด **บันทึก** เท่านั้น
  จากนั้นจะทำงานต่อไป และตัวที่ปิด จะหยุดทำงาน
- **เฉพาะไฟล์นั้น** เอดิเตอร์จำ SHA-256 ของไฟล์ไว้ DLL ที่เปลี่ยน (อัปเดตม็อด) คือ
  โค้ดอื่น: จะปิดอยู่ จนกว่าผู้เล่นจะเปิดอีกครั้ง ไบต์ที่ตรวจ คือไบต์ที่โหลด
- **ทำไมจึงไม่ทำงาน** "it is not marked as an extension ([assembly: WorldEditorExtension])" (ไม่ได้ทำเครื่องหมาย
  เป็นส่วนขยาย) "it needs a newer editor (API …; this one has …)" (ต้องใช้เอดิเตอร์รุ่นใหม่กว่า)
  "its entry … is not an IWorldEditorExtension" (จุดเริ่มต้น … ไม่ใช่ IWorldEditorExtension) หรือ exception ที่ `Register` โยนออกมา

### ฮุก

| ฮุก | สิ่งที่เอดิเตอร์ทำกับฮุกนี้ |
|---|---|
| `AddDecoder(key, IDataDecoder)` | ตัวตรวจดูข้อมูล แสดงค่าไบต์อาร์เรย์ เป็นคำของคุณ ใต้ค่า (แทนที่จะแสดงแค่ขนาด) `Describe` คืนบรรทัดสั้นๆ ไม่กี่บรรทัด หรือ `null` เมื่อไบต์ไม่อยู่ในรูปแบบที่อ่านได้ เมื่อส่วนขยายสองตัว อ่านคีย์เดียวกัน ตัวแรกที่ให้ข้อความ จะชนะ |
| `AddCopyRewriter(ICopyRewriter, keys)` | วัตถุแต่ละชิ้นของสำเนาที่วาง ที่มีคีย์ใดคีย์หนึ่ง จะถูกส่งให้คุณ (`ICopy`) หลังการเชื่อมโยง ของเอดิเตอร์เอง (`links`) พร้อม id ใหม่ของสำเนา แทน id ของต้นฉบับ (`IIdMap.TryGetNew` เป็น false เมื่อวัตถุที่มี id เดิม ไม่ได้ถูกคัดลอก) เปลี่ยนค่าในที่ (`SetInt`, `SetQuaternion`, `SetBytes`… `null` ลบค่าออก) คีย์เหล่านี้เป็นของคุณ: `dropOnCopy` จะไม่ลบออกอีก |
| `AddAreaCopier(id, IAreaCopier)` | สิ่งที่ม็อดของคุณเก็บไว้ เกี่ยวกับที่หนึ่ง ที่ไม่มีวัตถุที่คัดลอกใดถือไว้ (บันทึกหินที่ขุดออก ในตัวเก็บข้อมูล ที่เอดิเตอร์ไม่เคยคัดลอก) จะไปพร้อมสำเนาของเอดิเตอร์ เมื่อผู้เล่นคัดลอก (ส่วนที่เลือกของเครื่องมือ ขอบเขต หรือวัตถุของเครื่องมือ เลือก) `Copy(area, region)` จะได้พื้นที่ และสิ่งที่ถูกคัดลอก (`CopyRegion`: `Outline` และ `Contains(x, z)` เป็นเมตรของโลก และ `Middle`) และคืนไบต์ของคุณเอง (หรือ `null`): เก็บตำแหน่ง เป็นออฟเซ็ตจากจุดกลาง เพราะสำเนาอาจถูกวางที่ใดก็ได้ หมุน และสะท้อน แม้ในโลกอื่น ไบต์จะไปพร้อมสำเนา และลงในไฟล์พิมพ์เขียว ใต้ชื่อม็อดของคุณ และ `id` (ตัวอักษร ตัวเลข จุด ขีด และขีดล่าง) เมื่อวาง `Paste(area, bytes, copies)` จะถูกเรียกครั้งเดียว พร้อมทุกสำเนา ที่การวางนั้นวางลง (`CopyPlacement`: `Middle` `Turn` และ `Mirror` ของสำเนา `Place(offset)` แปลงออฟเซ็ต จากจุดกลางเดิม เป็นจุดในโลกที่ตกลง `Yaw(yaw)` แปลงการหมุน) และพื้นที่ ตามที่การวางทิ้งพื้นดินไว้ `ToolEdit` ที่คุณคืน เป็นส่วนหนึ่งของขั้นตอนเลิกทำ ของการวาง ไบต์ที่ตัวคัดลอกไม่ทำงาน (ไม่ได้ติดตั้งส่วนขยายของคุณ) จะถูกข้ามไปในการวาง |
| `AddPlacer(IObjectPlacer, prefabs)` | วัตถุของพรีแฟบ ที่เอดิเตอร์ใส่ไว้ ที่ตำแหน่งของตัวเอง (จัดวาง วาง ย้าย หรือหมุน ด้วยเครื่องมือใดก็ได้ สคริปต์ หรือ Claude) จะถูกส่งให้คุณ ขั้นตอนละครั้ง ทั้งหมดพร้อมกัน (`ICopy` แต่ละชิ้น อยู่ในตำแหน่งใหม่ ค่าตามที่จะสร้าง ของสำเนาที่วาง หลังตัวเขียนสำเนาใหม่) พร้อมพื้นที่ ตามสภาพก่อนขั้นตอนนั้น โดยไม่มีวัตถุที่ขั้นตอนนั้นย้าย: ตั้งค่าที่ม็อดของคุณคำนวณ จากตำแหน่งที่วัตถุตั้งอยู่ (การหมุนที่เก็บแยก จากการหมุนของวัตถุ รางที่ยานพาหนะตั้งอยู่ ป้ายจอดที่ป้ายระบุ) แบบเดียวกับที่ม็อดทำ เมื่อผู้เล่นสร้าง สิ่งที่คุณตั้ง จะถูกบันทึกพร้อมขั้นตอน และนำไปใช้แบบไลฟ์พร้อมกัน `SetTurn` หมุนวัตถุ ตามที่จะสร้าง สำหรับม็อดที่เก็บวัตถุ แบบไม่หมุน และเก็บรูปทรงไว้ในค่า (หมุนค่า แล้วหมุนวัตถุกลับ ตั้งแต่ editor 1.119.0) วัตถุที่เปลี่ยนตรงที่ตั้งอยู่ (ตัวตรวจดูข้อมูล การแก้ไขของเครื่องมือ) ไม่ถือเป็นการวาง |
| `AddShapes(IShapeProvider, prefabs)` | วัตถุของพรีแฟบ จะถูกวาดด้วยรูปทรงของคุณด้วย: `Shape` สามเหลี่ยม ในเฟรมของวัตถุ (เมตร x ขวา y ขึ้น z หน้า ใช้ตำแหน่ง การหมุน และขนาดของวัตถุ) หรือในเฟรมของโลก (`WorldSpace = true`) แต่ละรูปทรงมีสีเดียว (แดง เขียว น้ำเงิน อัลฟา จาก 0 ถึง 1 อัลฟาต่ำกว่า 1: โปร่งใส) เรียงจุดตามเข็มนาฬิกา เมื่อมองจากด้านหน้า เหมือนใน Unity หรือมองเห็นได้ทั้งสองด้าน (`BothSides = true` สำหรับใบเรือ หรือผ้า) รูปทรงจะถูกวาด ตามชนิดของวัตถุ (ซ่อน เมื่อแผง มุมมอง ซ่อนชนิดนั้น) วัตถุที่เอดิเตอร์ไม่มีโมเดล จะวาดด้วยรูปทรงของคุณ อย่างเดียว (ไม่มีกล่องแทนที่) และเลือก และตีกรอบ ด้วยกล่องของรูปทรง ที่คุณให้ไว้ สำหรับพรีแฟบของวัตถุ ที่ไม่มีข้อมูล (ที่อยู่ในเฟรมของวัตถุเอง) รูปทรง ที่มีสามเหลี่ยม อ้างถึงมุมที่ไม่มี หรือมุมที่ไม่ใช่ตัวเลข จะไม่ถูกวาด |
| `AddLinkPlacer(ILinkPlacer, prefabs)` | ส่วนที่เชื่อมโยง (`links` ในแมนิเฟสต์ของคุณ) วางตรงที่ม็อดของคุณสร้าง เมื่อข้อมูลอย่างเดียว ไม่ได้บอก `FrameOf(obj)` สำหรับวัตถุของพรีแฟบ ที่มีส่วนต่างๆ: เฟรมที่ส่วนต่างๆ แขวนอยู่ ในเฟรมของวัตถุเอง (`LinkFrame`: ออฟเซ็ต และการหมุน แท่นของแท่นหมุน ตามที่ม็อดของคุณหมุน หรือย้ายไว้) หรือ `null` สำหรับเฟรมของวัตถุเอง `PlaceOf(part, parent)` สำหรับส่วนของพรีแฟบ: ตำแหน่งที่ตั้งอยู่ ในเฟรมของสิ่งที่แขวนอยู่ แทนออฟเซ็ต และการหมุน (ส่วนนั้น อยู่ที่ตำแหน่ง และการหมุน ที่เกมบันทึก พาเรนต์ตามที่วาด เฟรมของพาเรนต์ จะไม่ถูกใช้ในกรณีนั้น) หรือ `null` สำหรับตำแหน่ง ตามการเชื่อมโยง การย้าย การคัดลอก และการลบ ยังเป็นไปตามการเชื่อมโยง |
| `AddGroundCuts(IGroundCutter, prefabs)` | พื้นดินจะไม่ถูกวาด ภายในเส้นรอบ (`GroundCut`) ที่คุณให้ไว้ สำหรับวัตถุของพรีแฟบ: จุดบนพื้นดิน (x, z) ในเฟรมของวัตถุ หรือในเฟรมของโลก (`WorldSpace = true`) อย่างน้อยสามจุด เรียงไปทางใดก็ได้ (เส้นรอบที่ตัดกันเอง จะตัดตามกฎคู่-คี่) การคลิกตรงนั้น จะทะลุผ่านรู พื้นดินของเอดิเตอร์ เป็นแผนที่ความสูง ที่มีจุดทุกเมตร: การตัด จะละพื้นดิน ระหว่างจุดที่อยู่ในเส้นรอบ ขอบจึงเป็นไปตามกริด 1 m นั้น และสิ่งที่เห็นทะลุ คือสิ่งที่คุณวาดไว้ข้างล่าง (รูปทรง) และด้านล่างของพื้นดิน |
| `AddScene(ISceneProvider)` | สิ่งที่ม็อดของคุณ ทำกับพื้นที่ทั้งหมด วาดลงในพื้นที่: `Build(area)` ถูกเรียกบน worker ทุกครั้งที่เปิดพื้นที่ และอีกครั้ง เมื่อวัตถุ พื้นดิน หรือเกมเปลี่ยน (หรือคุณเรียก `Host.Redraw()`) และคืน `SceneLayer` (หรือ `null`) `Meshes` ของเลเยอร์ (`SceneMesh`: มุมและนอร์มอล ในเฟรมของโลก เมตร สามเหลี่ยมเรียงจุด ตามเข็มนาฬิกา เมื่อมองจากด้านหน้า เหมือนใน Unity) จะวาดด้วยรูปลักษณ์พื้นดินของเกม เมื่อมี `BiomeColors` (สีพื้นดินของแต่ละมุม ตามที่ `area.BiomeColor` ให้) และระบายจาก `Mask` (เท็กซ์เจอร์เล็กๆ ของมาสก์การระบายพื้นดิน `MaskTexture`) ที่ `MaskUvs` เมื่อไม่มีสีไบโอม จะวาดด้วย `Color` การคลิก จะตกลงบนเมชเหล่านี้ (เว้นแต่ `Pickable = false`) `Holes` ของเลเยอร์ (`GroundHole`: สี่เหลี่ยมผืนผ้า เป็นเมตรเต็ม) ทำให้พื้นดินของเอดิเตอร์ ไม่ถูกวาด ทีละช่อง ตรงตามขอบพอดี: วาดสิ่งที่มาแทน `area` (`IAreaView`) ให้ขอบเขต วัตถุของพรีแฟบหนึ่ง ตามสภาพ พร้อมการเปลี่ยนแปลง ที่ยังไม่บันทึก (`ObjectsOf` รวมตัวเก็บข้อมูลของคุณ) ความสูงของพื้นดิน ตามที่เกมแสดง (`GroundHeight` ระหว่างจุดที่ห่างกันหนึ่งเมตร ตามสามเหลี่ยมของเกมเอง) ไบโอม จุดหนึ่งอยู่ใน ดินแดนเหนือสุด หรือ ดินแดนเถ้าถ่าน หรือไม่ และสีกับการระบายพื้นดิน ที่เมตรเต็ม (`BiomeColor`, `GroundMask`) คำนวณทุกอย่าง จากพื้นที่ทุกครั้ง ไม่เก็บอะไรไว้ระหว่างการเรียก |

### ตัวสร้างโลก

ม็อดสร้างโลก แทนที่พื้นดินของเกม และทำเครื่องหมายโลกที่สร้าง: ไฟล์โลก ขึ้นต้นด้วย -1
ในตำแหน่งที่เป็น เวอร์ชันไฟล์ของเกม ตามด้วย id ของตัวสร้าง (สตริง) แล้วตามด้วยสิ่งที่ม็อดเก็บไว้ (Riverheim ก่อน
1.3: เวอร์ชันไฟล์ของเกม แล้วพรีเซ็ต) เอดิเตอร์ปฏิเสธโลกแบบนี้ เว้นแต่จะมีส่วนขยาย ที่ทำงานอยู่ ลงทะเบียน
ตัวสร้าง ด้วย id นั้น เหมือนที่เกม ที่ไม่มีม็อด ปฏิเสธ: แสดงในรายการ เป็นสีเทา พร้อมเหตุผล (ระบุ id ใน
`worldGenerators` ของแมนิเฟสต์ เพื่อให้เอดิเตอร์บอกได้ ว่าขาดอะไร)

ม็อดที่เสียบเข้ากับ [Worldhalla](https://thunderstore.io/c/valheim/p/Gurebu/Worldhalla/) (Riverheim ตั้งแต่ 1.3) จะให้
Worldhalla ทำเครื่องหมายโลกแทน โดยมี id และการตั้งค่า ของตัวสร้าง อยู่ในเฮดเดอร์ของ Worldhalla เอง ลงทะเบียน
ตัวสร้างสำหรับโลกเหล่านั้น ด้วย id `worldhalla:` ตามด้วย id ของตัวสร้างของคุณ ใน Worldhalla (ของ Riverheim:
`worldhalla:dev.gurebu.riverheim`): `ReadHeader` จะได้รับเวอร์ชันไฟล์ของเกม ตามด้วยการตั้งค่าของคุณ ตามที่ Worldhalla
เก็บไว้ และต้องอ่านให้ครบ โลกที่เฮดเดอร์ Worldhalla มาจาก Worldhalla ที่ใหม่กว่า 1.0 (รูปแบบ หรือ
การตั้งค่าของ Worldhalla เอง) จะถูกปฏิเสธ พร้อมเหตุผล `IWorldGenerator` ของคุณ ให้:

- `Id`, `PluginId` (GUID ของ BepInEx ของม็อด: ในโหมดไลฟ์ คุณจะได้รับแจ้ง เวอร์ชันที่เกมรัน) และ `Name`
- `ReadHeader(file, out fileVersion)` และ `WriteHeader(file, fileVersion, settings)`: สิ่งที่ตามหลัง id อ่านและ
  เขียน ในรูปแบบของเกม (`IWorldFileReader`, `IWorldFileWriter`) การตั้งค่าของคุณ เก็บเป็น `GeneratorSettings` (
  คำอธิบายสำหรับผู้เล่น และค่าของคุณเอง) โยน `InvalidDataException` พร้อมเหตุผล สำหรับผู้เล่น เมื่อ
  อ่านเฮดเดอร์ไม่ได้
- `Problem(settings)`: เหตุที่โลกแบบนั้น วาดไม่ได้ อย่างรวดเร็ว (ถูกถามทุกโลก ที่หน้าเริ่มต้นแสดง) หรือ null
- `Open(settings, gamePluginVersion)`: พร้อมวางผังโลก เมื่อเปิดโลก (`IWorldLayout`: `Version` ของคุณ
  การวางผัง `Slow` หรือไม่ และ `LayOut(seed)`) โยน `InvalidOperationException` พร้อมเหตุผล เมื่อทำไม่ได้
- `LayOut(seed)` ให้ `IGroundLayout`: ไบโอม (ค่าของเกม) ความสูงพร้อมมาสก์ และ forest
  factor ที่จุดหนึ่ง แทนเนื้อหาของ GetBiome, GetBiomeHeight, GetAshlandsHeight และ
  GetForestFactor ของเกม (ถูกถามจากหลายเธรด) การยืดของ Expand World ยังมาก่อนคำตอบของคุณ ส่วนตัวคูณความลึก และ
  ป่า มาหลัง เหมือนที่แพตช์ของม็อด มาบรรจบกันในเกม เอดิเตอร์ไม่วางผังน้ำของเกม
- `NewWorldSettings()`: การตั้งค่าที่โลกใหม่ได้รับ (หน้า โลกใหม่ นำเสนอตัวสร้างของคุณ โดยเลือกไว้ก่อน) หรือ
  null
- `Notes(settings, expandWorld)`: สิ่งที่การตั้งค่าของ Expand World (`ExpandWorldSettings`) ทำอย่างอื่น กับโลกของคุณ สำหรับ
  ล็อก

สิ่งอื่นใด ที่ตัวสร้างของคุณโยนออกมา ถือเป็นความผิดพลาด: ส่วนขยายจะถูกปิด และผู้เล่นจะได้รับแจ้ง ว่าแอดออนล้มเหลว

### กฎของโลก

ม็อดสร้างโลก ที่เปลี่ยนการสร้างโลกของเกมเอง ผ่านการตั้งค่า และไฟล์ข้อมูล (โลกที่ใหญ่ขึ้น ไบโอม
สถานที่ และพืชพรรณของตัวเอง แบบที่ Expand World ทำ) ไม่ได้วางผังโลกเอง: ตัวสร้างของเอดิเตอร์
ทำตามกฎที่ได้รับ บิลด์ส่วนขยายของคุณ สำหรับ net10.0 (บิลด์ `net10.0` ของ SDK มีโมเดลกฎ
`WorldRules` และชนิดที่อยู่ในนั้น ใน namespace `ValheimGen`) และลงทะเบียน `IWorldRulesProvider`:

- `ForWorld(world)`: กฎที่โลกเปิดด้วย `WorldRulesRequest` ให้ `Name`
  `StartingGlobalKeys` ที่ไฟล์โลกเก็บไว้ (การตั้งค่าของม็อด ที่เก็บไว้ตรงนั้น) `LoadedGlobalKeys` ที่เซฟมี
  `GridWidth` ที่ไฟล์ chunk วางอยู่ และเกมที่โลกรันอยู่ เมื่อเป็นไลฟ์ (`Live` มิฉะนั้น null): อ่าน
  ไฟล์ของม็อด จากเกมในกรณีนั้น ผ่าน `Live.Plugins()`, `Live.ConfigFile(path)` และ `Live.ConfigFolder(path)`
  (ใต้ BepInEx/config ของเกม null จาก WorldEditorBridge ที่เก่ากว่า 1.54.0) มิฉะนั้น จาก `Host.BepInExFolders`
- `ForNewWorld()`: กฎที่ใช้สร้าง และดูโลกใหม่ (หน้า โลกใหม่)

คืน null (หรือ `WorldRules.Vanilla`) เมื่อม็อดของคุณ ไม่เปลี่ยนโลก (ไม่ได้ติดตั้ง หรืออยู่ที่ค่าเริ่มต้น): จะถาม
ผู้ให้กฎตัวถัดไป และถ้าไม่มี โลกจะเป็นของเกมเอง กฎของสถานที่ พืชพรรณ และห้อง สร้างขึ้น
เทียบกับของเกมเอง (`Host.World`: `Locations` เมื่อ `ReadLocations()` อ่านแล้ว `Vegetation`
`HasPrefab(name)` และ `IsGameRoom(name)`) `WorldRulesText.Describe(rules)` บอกว่ากฎเปลี่ยนอะไร ในไม่กี่คำ สำหรับ
บรรทัดล็อกของคุณ ผู้ให้กฎที่โยน exception ถือเป็นความผิดพลาด: ส่วนขยายจะถูกปิด และจะถามตัวถัดไป

### กฎ

- **ทำงานเร็ว ไม่เก็บสถานะ** ฮุกถูกเรียกจากหลายเธรด พร้อมกัน และบ่อย (ทุกครั้ง
  ที่วาดรูปทรง และการตัดใหม่ ทุกวัตถุที่วาง): ไม่เก็บสถานะ ระหว่างการเรียก (หรือล็อกไว้)
  และคืนค่าให้เร็ว
- **ห้ามโยน exception** ฮุกที่โยน exception จะทำให้ส่วนขยายปิด จนกว่าเอดิเตอร์จะเริ่มใหม่
  (การตั้งค่า บอกเหตุผล และล็อกด้วย) เอดิเตอร์ทำงานต่อ โดยไม่มีส่วนขยายนั้น ในโค้ดที่ทำงานต่อ หลัง
  ฮุกคืนค่าแล้ว (การเรียก `async` ไปยังเกม) ให้ดักจับทุกอย่างเอง เหมือนที่ `LiveLink` ของตัวอย่าง
  ทำ
- **เวอร์ชัน** `SdkInfo.ApiVersion` คือเวอร์ชันของ API (ตอนนี้คือ 1) และแอตทริบิวต์บันทึกเวอร์ชัน
  ที่คุณใช้บิลด์ เอดิเตอร์รันส่วนขยาย ที่บิลด์กับเวอร์ชันของตัวเอง หรือเวอร์ชันก่อนหน้า ฮุกใหม่
  มาเป็นส่วนเพิ่ม เวอร์ชันจะเปลี่ยน เฉพาะเมื่อ API เปลี่ยนแบบเข้ากันไม่ได้

## แอดออน

ส่วนขยาย ส่งมาพร้อมม็อด เมื่อผู้สร้างม็อด ไม่ได้ทำไว้ (หรือม็อดไม่ได้รับการดูแล
อีกต่อไป) ใครก็ทำได้: **แอดออน** คือ `worldeditor.json` และส่วนขยาย สำหรับ **ม็อดของ
คนอื่น** ที่ปล่อยแยกต่างหาก ซึ่งผู้เล่นติดตั้งไว้ข้างเอดิเตอร์ ตัวม็อดเอง ยังคงเหมือนเดิม
ใน `BepInEx/plugins` แอดออนแค่สอนเอดิเตอร์ ให้รู้จักม็อดนั้น

```
ValheimWorldEditor/                the editor's folder (on macOS: the folder holding ValheimWorldEditor.app)
  ValheimWorldEditor(.exe)
  addons/
    Tunnels/                       one folder per add-on, named as you like
      worldeditor.json
      Tunnels.WorldEditor.dll
```

- **ไฟล์ของแอดออน** คือ `worldeditor.json` แบบด้านบน (ป้ายข้อมูล พรีแฟบ การเชื่อมโยง `extension`
  `gameComponents`) โดยมีคีย์เพิ่มอีกหนึ่งตัว: `"serves": "TheirMod.dll"` ชื่อไฟล์ DLL ของม็อด
  แอดออนจะถูกใช้ ขณะที่มี DLL ชื่อนั้น อยู่ในโฟลเดอร์ปลั๊กอิน ที่เอดิเตอร์รู้จัก
  (การตั้งค่า โฟลเดอร์ BepInEx) ที่ใดก็ได้ใต้ `plugins` และไม่ถูกใช้ในกรณีอื่น เมื่อไม่มี `serves`
  แอดออนจะถูกใช้เสมอ (เครื่องมือของคุณเอง ที่ไม่ได้ทำเพื่อม็อดใด) `serves` ที่ไม่ใช่ชื่อไฟล์ธรรมดา
  ที่ลงท้ายด้วย `.dll` หรือไฟล์ ที่เป็นเวอร์ชัน ที่เอดิเตอร์นี้อ่านไม่ได้ จะทำให้แอดออน
  ถูกข้ามไป (ล็อกบอกเหตุผล)
- **ส่วนขยายของแอดออน** สร้างแบบเดียวกับส่วนขยายอื่น (ดู [การสร้างส่วนขยาย](#การสรางสวนขยาย)): DLL เดียว ใน
  โฟลเดอร์ของแอดออน ทุกฮุกและกฎ เหมือนกัน
- **เปิดใช้เมื่อติดตั้ง** การติดตั้งแอดออน เป็นการเลือกของผู้เล่น แอดออนจึงทำงาน โดยไม่ต้องเปิด
  ใน การตั้งค่า การตั้งค่า แสดงแอดออนไว้ใต้ **แอดออน** แต่ละตัว มีสวิตช์ที่ปิดได้
  โดยไม่ต้องลบ (เมื่อปิด จะไม่ใช้ส่วนใดของแอดออน) และสถานะของแต่ละตัว: "รอม็อดของแอดออน:
  TheirMod.dll ไม่อยู่ในโฟลเดอร์ปลั๊กอินด้านบน" "ทำงานอยู่" "ไม่ทำงาน: …" ว่าแอดออน
  มีแค่ข้อมูลบอกเอดิเตอร์ หรือว่าปิดอยู่
- **คำของม็อดเองชนะ** ไฟล์ของแอดออน ถูกอ่านก่อนของม็อดเอง: ถ้าม็อด
  ส่ง `worldeditor.json` ของตัวเองมาในวันหนึ่ง สิ่งที่ไฟล์นั้นบอก จะแทนที่สิ่งที่แอดออนบอก (ส่วน
  ส่วนขยายของม็อดเอง ยังต้องให้ผู้เล่นเปิดสวิตช์ เหมือนเดิมเสมอ)
- **ปล่อยเป็นไฟล์ `.zip` ที่มีโฟลเดอร์ของแอดออน** ให้ผู้เล่นแตกไฟล์ลงใน `addons` แพ็กเกจของ
  เอดิเตอร์ มาพร้อมโฟลเดอร์นั้น ที่ว่างเปล่า ยกเว้น `README.txt`
- **repository ของเอดิเตอร์เอง มีแอดออนอยู่ไม่กี่ตัว** (`addons/` แต่ละตัว ปล่อยเป็น zip ของตัวเอง ข้าง
  แพ็กเกจของเอดิเตอร์: ดู [development.md](../development.md#add-ons-in-this-repository)) ของคุณ
  อยู่ที่ใดก็ได้

## โหมดไลฟ์

เมื่อเชื่อมต่อกับเกมที่กำลังรัน (โหมดไลฟ์) เอดิเตอร์นำการเปลี่ยนแปลงไปใช้ ผ่าน
ปลั๊กอิน WorldEditorBridge ซึ่งทำลาย สร้าง และย้ายวัตถุในเกม ม็อดที่สร้าง
สิ่งต่างๆ จากวัตถุของตัวเอง ขณะที่เกมรัน (ยานพาหนะจากชิ้นส่วน อุโมงค์จากสิ่งที่ขุด)
จะเห็นการเปลี่ยนแปลง ของเอดิเตอร์ ในการโหลดครั้งถัดไปเท่านั้น เว้นแต่ปลั๊กอินของม็อดเอง จะมีส่วนร่วม บริดจ์
ให้ปลั๊กอินของม็อดสองอย่าง ผ่าน `WorldEditorBridge.Api.dll`: ไฟล์นี้มาพร้อมบริดจ์ ในโฟลเดอร์
`plugins` ของบริดจ์ และใน zip ของ SDK และไม่มีชนิดของเกม หรือของ Unity อัปเดตเกม จึงทำให้
ไฟล์นี้เสียไม่ได้

### ฝั่งปลั๊กอินของคุณ

ลงทะเบียนจาก `Awake` ของปลั๊กอิน โดยมี soft dependency กับบริดจ์ และเก็บโค้ด
ที่แตะ API ไว้ในคลาสของตัวเอง: ปลั๊กอินของคุณ จึงโหลดได้แม้ไม่มีบริดจ์ จาก
`sdk/samples/ExampleVehicles.Bridge` ของตัวอย่าง:

```csharp
[BepInPlugin(PluginId, "ExampleVehicles", "1.0.0")]
[BepInDependency(BridgeApi.BridgeGuid, BepInDependency.DependencyFlags.SoftDependency)]
public sealed class ExampleVehiclesBridgePlugin : BaseUnityPlugin
{
    public const string PluginId = "ExampleVehicles";

    private void Awake()
    {
        if (Chainloader.PluginInfos.ContainsKey(BridgeApi.BridgeGuid))
        {
            BridgeLink.Register(Logger);   // a class of its own: this plugin loads without the bridge
        }
    }

    private void OnDestroy()
    {
        if (Chainloader.PluginInfos.ContainsKey(BridgeApi.BridgeGuid))
        {
            BridgeLink.Unregister();       // BridgeApi.Remove(PluginId)
        }
    }
}

internal static class BridgeLink
{
    public static void Register(BepInEx.Logging.ManualLogSource log)
    {
        BridgeApi.AddRoutes(ExampleVehiclesBridgePlugin.PluginId, new Routes());          // answers the editor's calls
        BridgeApi.AddListener(ExampleVehiclesBridgePlugin.PluginId, new Listener(log));   // told what the editor applied
    }

    public static void Unregister() => BridgeApi.Remove(ExampleVehiclesBridgePlugin.PluginId);
    // Routes and Listener: see the sample.
}
```

| ฮุก | สิ่งที่บริดจ์ทำกับฮุกนี้ |
|---|---|
| `AddListener(modId, IBridgeListener)` | `OnApplied(AppliedChanges)` ถูกเรียกบนเธรดหลักของเกม ทันทีหลังการนำไปใช้ ของเอดิเตอร์แต่ละครั้ง พร้อมสิ่งที่เปลี่ยน: `Created` และ `Destroyed` วัตถุที่สร้าง และทำลาย (แต่ละชิ้น มี `User` และ `Id` ของ ZDOID แฮชของพรีแฟบ และตำแหน่ง) `Moved` วัตถุที่ย้าย ภายใต้ ZDOID เดิม (บริดจ์ 1.40.0 ขึ้นไป: `From` ตำแหน่งเดิม `To` ตำแหน่งปัจจุบัน วัตถุที่ผู้เล่นโหลด ทั้งตำแหน่งเก่าและใหม่ไว้ จะถูกสร้างใหม่แทน และอยู่ใน `Created` และ `Destroyed` ตั้งแต่ 1.97.0 วัตถุที่เอดิเตอร์ เปลี่ยนข้อมูล ก็อยู่ที่นี่ด้วย โดยมีข้อมูลใหม่อยู่แล้ว) `TerrainZones` โซนที่พื้นดินถูกเขียนใหม่ `ResetZones` โซนที่ถูกล้าง เพื่อสร้างใหม่ ประกอบสิ่งของของคุณ กลับขึ้นมาใหม่ ที่นี่ exception จะถูกบันทึก ลงในล็อกของเกม และไม่เปลี่ยนสิ่งใด ที่เอดิเตอร์ทำไป |
| `AddRoutes(modId, IBridgeRoutes)` | `Handle(name, body)` ตอบ `POST /mods/<modId>/<name>` บนเธรดหลักของเกม เป็นไบต์ในรูปแบบใดก็ได้ ที่คุณและส่วนขยายเอดิเตอร์ ตกลงกัน `null` ตอบ 404 ("the mod has no route of that name") exception ตอบ 500 พร้อมข้อความ บริดจ์รอเธรดหลัก ไม่เกิน 30 วินาที: ทำให้เร็ว หรือตอบ "started" แล้วให้ส่วนขยาย ถามอีกครั้ง body ของการเรียก มีขนาดไม่เกิน 16 MB |
| `Remove(modId)` | นำ route และ listener ของคุณออก (ปลั๊กอินที่กำลังปิดตัว) |

วัตถุที่บริดจ์สร้าง ย้าย หรือเปลี่ยน จะถูกส่งให้ม็อดของเกม แบบเดียวกับที่เกมส่ง
วัตถุที่มาจากเกมอื่น: ข้อมูลผ่าน `ZDO.Deserialize` อีกครั้ง (ค่า
เดิม) ม็อดที่รู้จักวัตถุ ด้วยการแพตช์เมธอดนี้ (ZdoWatcher ของ ValheimRAFT ซึ่งหาเรือ และ
สิ่งที่เชือกผูกไว้ จาก id) จะรู้จักวัตถุที่วางทันที โดยไม่ต้องมี listener ของตัวเอง

การลงทะเบียนอีกครั้ง ด้วย id เดิม จะแทนที่สิ่งที่ลงทะเบียนไว้ก่อน id ของม็อดเป็นของคุณ (id ของ
ปลั๊กอิน ก็ใช้ได้ดี): ตัวอักษร ตัวเลข จุด ขีด และขีดล่าง 1 ถึง 100 ตัว id แบบอื่น
จะโยน exception `BridgeApi.Version` คือเวอร์ชันของ API (ตอนนี้คือ 1) บริดจ์รันปลั๊กอิน ที่บิลด์กับ
เวอร์ชันของตัวเอง หรือเวอร์ชันก่อนหน้า และส่วนเพิ่ม จะคงเวอร์ชันไว้ `GET /mods` บนบริดจ์ แสดงเวอร์ชัน API
และ id ที่ลงทะเบียน

### ฝั่งส่วนขยายของคุณ

ส่วนขยายของคุณ เข้าถึงเกมผ่าน `ILiveGame`: จาก `registry.Host.Live` เมื่อใดก็ได้ (null เมื่อ
เอดิเตอร์ไม่ได้เชื่อมต่อ) หรือใน `OnConnected` ของ live listener

- `Mods`: id ที่ลงทะเบียนกับบริดจ์ ตามที่บริดจ์รายงาน ตอนเปิดโลก
  (ปลั๊กอินที่ลงทะเบียนภายหลัง จะเห็นในการเชื่อมต่อครั้งถัดไป)
- `CallAsync(modId, name, body)`: เรียก route ของคุณ และคืนไบต์ของคำตอบ จะโยน exception เมื่อ
  ม็อด หรือ route ไม่ได้ลงทะเบียน เมื่อ route ล้มเหลว (พร้อมข้อความของเกม) หรือเมื่อ
  เข้าถึงเกมไม่ได้
- `Plugins()`, `ConfigFile(path)` และ `ConfigFolder(path)`: ปลั๊กอิน BepInEx ที่เกมโหลด และไฟล์ หรือ
  รายการในโฟลเดอร์ ใต้ BepInEx/config ของเกม อ่านอย่างเดียว (null จากบริดจ์ที่เก่ากว่า 1.54.0 และสำหรับพาธ ที่
  ไม่มีอยู่) จะโยน `InvalidOperationException` เมื่อบริดจ์ปฏิเสธพาธ (นอกโฟลเดอร์ หรือเกิน 4 MB)

ถามเกมถึงสิ่งที่มีแค่เกมรู้ (สิ่งที่ม็อดของคุณสร้างในโค้ด) เก็บไว้ แล้วเรียก
`registry.Host.Redraw()` ให้รูปทรง และการตัดของคุณ ถูกสร้างใหม่ `LiveLink` ของตัวอย่าง เรียก
route `ping` ของปลั๊กอิน เมื่อเอดิเตอร์เชื่อมต่อ และบันทึกคำตอบลงล็อก ปลั๊กอินของตัวอย่าง ยังตอบ
`players` (จำนวนผู้เล่นในเกม) ด้วย

เมื่อเปิดโลกแบบไลฟ์ ล็อกของเอดิเตอร์ จะระบุชื่อม็อดที่ลงทะเบียน ("bridge mods: …")
